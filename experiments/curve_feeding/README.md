# 曲线积分调长实验（独立入口）

本目录只替换模式4的目标形状生成器。主仿真、主实机文件不改动。

启动手动仿真：

```powershell
conda activate mujoco
python .\experiments\curve_feeding\manual_mujoco.py
```

仍使用 Ctrl+U 形成、Ctrl+4 选择调长、Ctrl+J/H 启动正/反向相对调长、Ctrl+G 暂停/继续、Ctrl+L 强制推进一帧、Ctrl+Y 返回、Ctrl+X 失能。方向含义、单步任务量与主入口相同。实验后端也用于本进程内模式5/6调用的调长部分，但本轮不据此宣称越障重新验证通过。

执行比较与验证：

```powershell
python -m experiments.curve_feeding.check_equivalence
python -m experiments.curve_feeding.validate_mujoco --output validation/results/curve_feeding_rerun
python -m experiments.curve_feeding.review --input validation/results/curve_feeding_rerun
```

物理验证会保留原始证据；再次复现时换一个输出目录，避免覆盖上次运行。

场景、起始窗口和基础幅值可在 `manual_mujoco.py` 顶部修改。运行日志另存到 `logs/curve_feeding_experiment/`，包含曲线各子段的长度、曲率和弯曲方向。

本轮结论和视频见 [验证报告](../../validation/reports/curve_feeding_20261108/README.md)。曲线迁移复现了原行为；原长度代理在短端姿态仍存在明显偏差，不能把兼容性通过说成毫米精度通过。

## 本轮预先约定

假设：把旧模板、肩部偏置和中部转角重分配表达为分段曲率并积分，可以保留原调长行为。第一轮是兼容迁移，不同时优化半径、速度或放宽反馈门槛。

固定：18关节、旧模型各连杆64.5 mm、直管直径110 mm、原动力学和反馈周期；双方使用同一初始实际状态和按键脚本。控制器只获得全关节角、时间戳和已知配置；世界位置、接触、力矩仅用于评价。

改变：目标角生成后端。J/H、角度观察器、长度代理、参考区段、进入预置、退出和局部缓冲直接继承当前控制器，不另写一套。

先做参数空间与已有实测记录的离线比较。物理实验先安排两个配对病例（原方法/新方法各一次，共4次）：中间姿态往返并穿插暂停/恢复及强制推进；接近一端后继续调长再反向。只有发现具体问题才增加有针对性的检查，不扩大无关场景。

验收：目标角在数值精度内一致，活动焦点相同；同反馈回放时阶段/长度估计/掩码一致；物理过程中实际长度变化方向和回程有效，开放ARC、接管与失能正常，无新增自碰撞/落地/限位问题。检查完整过程及结束后保持，记录实际状态、目标、使能、力矩和命令。若旧版本身失败，保留证据并明确区分兼容迁移与物理功能是否通过，不靠改上层逻辑把它掩盖。

这不是一段恒定半径圆弧的刚性平移。原法的交错pitch/yaw采样和肩部修正会产生多个子段，实验版明确保留它们。q仍是曲线分配参数，实际毫米量由原角度重建长度代理判断。两端标称直线不等于使能；是否失能仍由原交接逻辑决定。新实机的准确轴距尚未统一标定，本轮不能替代实机尺寸验证。
