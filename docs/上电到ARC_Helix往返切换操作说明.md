# 上电 → ARC → Helix → ARC：操作说明

适用于`codes/Rolling_Arc_Real.py`和`codes/Rolling_Arc_Debug_Mujoco.py`。**下文所有字母、数字和方向键都要同时按住Ctrl**，例如“按G”就是Ctrl+G。按住字母不放只算一次按键，连续动作使用G。

**整条路线：上电搭管 → 启动 → U形成ARC → 5、G自动准备前部 → 前部搭稳后L、G送尾 → Helix完成 → 7、G解缠并归中 → J/H正反ARC运动。**

## 1. 上电并形成初始ARC

| 什么时候 | 按什么／做什么 | 应看到什么 |
| --- | --- | --- |
| 初次上电 | 接好机器人电源、USB串口，将机器人中部搭在管道上，托好初始姿态 | J1为头部，J18为尾部；头尾有可下垂的余长 |
| 搭管后 | 在已有环境中运行下方实机命令 | 打开控制台和关节预览；此时只读反馈，尚未接管 |
| 准备形成圆弧 | 按 **U一次** | 默认J8–J13逐渐形成ARC，其他关节失能；程序提示“形成／静置” |
| 形成和静置完成 | 继续观察，暂不反复按U | 默认将非承载两端短时使能归零，再失能；这时预览可能短暂全蓝，结束后应只剩承载区域蓝色 |
| 已回到保持状态，两端归零已结束 | 按 **J/H** 正反单步，或 **G** 连续滚动／暂停 | 中部开放圆弧在管上滚动，两端保持失能；准备切换时按空格暂停 |

在仓库根目录运行：

```powershell
conda activate mujoco
python .\codes\Rolling_Arc_Real.py
```

仿真手调改为`python .\codes\Rolling_Arc_Debug_Mujoco.py`，其余按键相同。实机默认自动查找CH340；需要指定时在文件顶部把`PORT`改为实际端口，例如`'COM9'`。只运行一个入口。

预览中**蓝色使能、紫色失能**；角度图黑色为实测，橙色为使能关节目标。两端归零结束后会释放扭矩，受接触或摩擦影响仍可再次弯曲；K可核对“释放前最大角”和当前读角。

## 2. ARC切换成Helix

**一般可以直接按5，程序会按当前姿态判断是否需要先调长两侧，不要求你先手动调成固定长度。**

| 什么时候 | 按什么 | 应看到什么／下一步 |
| --- | --- | --- |
| ARC已搭稳，初始形成／归零已结束 | **5** | 选择ARC→Helix，先保持，不会只按5就完成全部运动 |
| 准备开始切换 | **G一次**；需要细看时用 **J单步** | 程序需要时自动调整两侧余长，再让前部逐渐形成螺旋；尾部尚未整体上管 |
| 前部已实际搭牢，K显示`front_seat`或`front_hold` | **L确认，再G** | L记录支撑并保持；G才开始接管尾段。不要只按L后一直等尾部运动 |
| 已进入送尾 | **G连续**，或每次 **J** 推进一小段 | 尾段沿曲线逐段接入，前部配合螺旋推进；最后整理成完整Helix |
| 控制台出现`complete`，机器人全身已形成Helix | 保持，准备进入下一节 | 此时已经完成5，不用再按G催进度；可以直接按7切回ARC |

若在`front_finish`时就已看到前部搭牢，可以提前L记录确认，再G继续衔接；进入`front_seat`后需要直接送尾时，可再L、G。**L负责确认，G负责执行**。K看阶段时，应同时观察实物是否贴管，不能只凭“目标角跟上”判断搭牢。

切换中的J每次最多执行`HELIX_STEP_S`秒，默认1秒；执行中重复J不追加。想持续走就按G，想停就再G或空格。这里的H不是倒放整个切换流程。

### 可选：先手动调两侧长度，再切换

在已搭稳的ARC上：**4 → J/H调长 → 本次动作结束或暂停 → 5 → 按上表继续**。

- 模式4的 **J：头侧增长、尾侧缩短；H：头侧缩短、尾侧增长**。头侧按J1定义，与屏幕左右无关。
- 一次J/H是一段调长任务，默认请求72 mm；G暂停／继续当前任务，Ctrl+-/=减半／加倍请求量。K显示进度。
- 若当前任务卡在接管／稳定采样，L沿本次任务方向强制推进一小步，发完保持；再L再推进。它与模式5中L的“搭稳确认”含义不同。
- 再按5会重新读取当前姿态，必要时继续自动调长。无需先返回初始的中间位置。

## 3. Helix切回ARC并自动归中

| 什么时候 | 按什么 | 应看到什么／下一步 |
| --- | --- | --- |
| 5已完成，全身Helix稳定搭管 | **7** | 按实测关节角选择Helix→ARC流程，先保持 |
| 准备开始 | **G连续**，或 **J单步** | 尾部逆向逐段解缠、失能下垂，前部保留承载螺旋；随后导出头端，形成开放半圆 |
| 半圆已经形成 | 继续G或J，不需要L确认 | 两端归零再失能，然后自动调整圆弧在蛇身上的位置，让两侧余长接近均衡 |
| 自动归中结束 | 继续观察最后一次归零 | 程序按最终使能范围再把两端临时使能到零、失能；承载半圆保持 |
| 提示“已交回基础圆弧并保持” | **J/H正反单步，G连续／暂停** | 使用刚形成的ARC继续运动，保留当前半径、位置和相位，不回跳初始J8–J13模板 |

切换中的J每次最多执行`HELIX_ARC_STEP_S`秒，默认1秒；H不倒放解缠。**完成后J/H才恢复基础圆弧的正反相位步长。**完成后若想继续走ARC，直接J/H/G即可；不要再按7，7表示新建一轮Helix→ARC。

K显示最终归零结果：`zero_then_disabled`表示释放前读角已接近零；`timeout_then_disabled`表示到时已释放，不能当作已归零成功。

## 4. 每个阶段怎么调快、调大步长

实机参数都在`codes/Rolling_Arc_Real.py`顶部。**改文件后退出旧Python，再重新启动才生效。**下面“数值增大更快”指代码中的指令速度，实际动作还会受目标限速、跟踪和机械接触影响。

| 想调整什么 | 改哪个参数 | 怎么理解 |
| --- | --- | --- |
| U形成初始ARC的速度 | `FORM_RATE_DEG_S` | 单位°/s，增大后建形更快 |
| U形成后的静置时间 | `SETTLE_S` | 秒；这是首次形成的等待，不是每次J/H都等待 |
| 两端归零速度／停留 | `END_ZERO_RATE_DEG_S / END_ZERO_HOLD_S / END_ZERO_MAX_S` | 分别为°/s、归零后保持秒数、最长执行秒数；7中归零速度还乘7的倍率 |
| 基础ARC每次J/H走多远，含7完成后 | `PHASE_STEP_RAD`；在线Ctrl+-/= | 默认0.10 rad；改0.30就是每次三倍相位行程，不等于三倍速度 |
| 基础ARC单步和连续动作速度，含7完成后 | `OMEGA_RAD_S`；在线Ctrl+右／左 | 单位rad/s；右／左每次增减0.05 |
| 基础ARC目标变化仍被限速 | `MAX_TARGET_RATE_DEG_S` | 单位°/s；与omega共同影响实际发送目标的变化快慢 |
| 模式4每次调多少长度 | `FEED_DISTANCE_M`；在线Ctrl+-/= | 单位m，实机默认0.072；每次任务的量，不是速度 |
| 模式4调长速度 | `FEED_RATE_JOINTS_S` | 单位“关节间距/秒”，增大更快；首次建立时间另看`FEED_PREPARATION_S` |
| 模式5自动调长、前部成形和首次送尾 | `HELIX_TRANSITION_SPEED_SCALE` | 1.0为基础速度，数值越大上述动作越快；不是5完成后普通ARC的速度 |
| 模式5自动调长仍慢 | `FEED_RATE_JOINTS_S` | 自动调长上限为此值×5的倍率；若`FEED_OPTIONS_OVERRIDE`设了`maximum_position_rate_joints_s`，以覆盖值为准 |
| 模式5单次J执行多少动作 | `HELIX_STEP_S` | 秒；增大使一次J执行更久，G连续不受这段预算限制 |
| 模式7解缠、半圆成形、自动归中整体快慢 | `HELIX_ARC_SPEED_SCALE` | 独立倍率；不叠乘5的倍率；完成后切回`OMEGA_RAD_S` |
| 模式7单次J执行多少动作 | `HELIX_ARC_STEP_S` | 秒；G用来连续执行 |

**简单调法：每次ARC单步太短改`PHASE_STEP_RAD`；基础ARC动作慢改`OMEGA_RAD_S`；模式4调长慢改`FEED_RATE_JOINTS_S`；切换5或7整体慢改对应的`SPEED_SCALE`。**

### 只想调某一小段时

通常先用上表；确实只想改某一段，再看这些项：

| 阶段 | 参数位置 | 作用 |
| --- | --- | --- |
| 5前部小幅就位 | `GRAVITY_ALIGN_RATE_RAD_S`，实际乘5倍率 | 相位推进速度；`HELIX_FRONT_SEAT_RAD`是总就位转角，增大它是多转一些 |
| 5首次送尾 | `GRAVITY_SHIFT_RATE_M_S / GRAVITY_RETURN_ROLL_RAD_S`，实际乘5倍率 | 分别控制直尾缩短与前部滚动配合。两者也供6后续回卷复用，改它们会同时影响6；只加快首次切换优先改5倍率 |
| 5尾段接入、曲线消除 | 同上和5倍率 | 接管、消除过渡弧有分段时间；最后`recover`还保留约5秒过渡，倍率不把整次流程等比例缩短 |
| 5最后恢复螺旋，`recover` | 目前没有顶部独立调速入口 | 在`_advance_recover`中使用`GravityMomentOptions.roll_rate`并保留约5秒过渡；压缩本段需要单独修改该函数，不能仅靠5倍率 |
| 5最后统一全身Helix | `HELIX_TRANSITION_SPEED_SCALE` | 最终归形目标角限速为18×倍率°/s，反馈确认时间仍按实际时间 |
| 7逆向解缠 | `HELIX_ARC_OPTIONS`中的`reverse_feed_m_s / reverse_roll_rad_s` | 送出直尾与配合滚动速度，实际乘7倍率；两者应配合调整 |
| 7建立退出过渡、形成半圆 | `lead_s / flatten_s` | 基础时长，实际时长随7倍率缩短；增大秒数会更慢 |
| 7自动归中 | `center_rate_m_s` | 最大材料移动速度，实际乘7倍率 |
| 7目标跟随速度 | `target_rate_deg_s` | 单位°/s，实际乘7倍率 |

`HELIX_ARC_OPTIONS['roll_rate_rad_s']`属于离线直接核心的续滚参数，**实机／手调7完成后用`OMEGA_RAD_S`**。静置和反馈周期仍按实际时间，不会随倍率全部等比例缩短。

仿真手调的基础幅值／频率另在`Rolling_Arc_Debug_Mujoco.py`顶部设`SIM_AMPLITUDE_DEG / SIM_OMEGA_RAD_S`；切换倍率、调长参数和J/H步长仍读取实机文件。实机和仿真几何分别使用各自尺寸。

## 5. 一时不知道下一步按什么

| 看到的情况 | 操作 |
| --- | --- |
| 想立即暂停并保持当前目标 | **Ctrl+空格**；G也可切换连续／暂停 |
| 想看当前模式、阶段、速度和下一步 | **K** |
| 5中前部已搭牢，但停在`front_hold`或`front_seat` | **L，再G** |
| 按L后不动 | L只确认并保持，**再G或J**才执行 |
| 5或7中反复按J提示“单步仍在执行” | 等这次单步结束，或用 **G** 连续；完成回到基础ARC后J/H才按相位累计 |
| 基础ARC中想每次走更多 | **Ctrl+=**，或改`PHASE_STEP_RAD`后重启 |
| 要结束控制 | **X全部失能，再Q退出** |

本说明描述当前程序操作；切换是否贴稳以实物为准。测试范围及已有高速归中形态偏差见[切换验证记录](../validation/reports/helix_arc_basic_return_20261108/README.md)，J/H等待与键盘修复见[按键核对](../validation/reports/basic_hotkey_response_20261108/README.md)。本路线只用5和7，不进入6的T管重力矩越障。
