# 固定窗口圆弧截面顺应：仿真实现

完成记录：2026-10-12。研究对象是局部使能的开放圆弧，当前窗口固定为J8–J13；其余关节失能。滑动窗口与实机移植不在本批次实现范围。

后续状态：用户已授权先移植固定窗口截面顺应。当前`codes/Rolling_Arc_Real.py`提供基础/固定截面Ctrl+E开关，详细操作见[实机说明](实机调试代码说明.md)。本页仍记录原固定窗口仿真批次，新增移植的离线检查不等于实机通过；滑窗接触观测方法未移植。

## 实际完成与边界

完成Python独立几何计算、截面顺应、开放约束、MuJoCo入口和有限实验。直管、小幅渐扩—渐缩、113→163 mm突变、90°柔弯、45°变径弯及真正90°变径弯通过本批次形态/支撑/推进检查。连续90°急弯也完成全身通过，拐角处单截面管轴包绕不可观测，完整形态验收保留未确认；没有修改门槛或把这项算成通过。

名义形态仍为半圆。实际离散机器人在基础步态下最大包绕212.71°，因此本批次冻结实际允许带150°–218°、目标连续截面总转角≤190°、端部间距/主动骨架长度≥0.4。218°是R0基础偏差加5°取整得到的工程容差，不能称为精确180°。目标连续截面、身体几何、真实管轴包绕是三种不同量。

所有通过的变化场景全身体越过后观察至少3个周期。几何顺应没有再次累计闭合成螺旋包绕；基础对照同样通过当前两类直管变径，尚未证明新增顺应相对基础步态的性能优势。身体拟合圆半径主要随相位波动，不能宣称已实现精确管径跟踪。

## 从2023方法保留了什么

参考方法是Takemori、Tanaka、Matsuno的《Adaptive Helical Rolling of a Snake Robot to a Straight Pipe With Irregular Cross-Sectional Shape》，IEEE TRO 39(1)，437–451，2023，DOI [10.1109/TRO.2022.3189224](https://doi.org/10.1109/TRO.2022.3189224)。实现以参考仓库的`Kinematics.cs`、`RollingAxis.cs`、`CrossSectionCurve.cs`及`snake_control/pole_compliance.py`为对照。

保留的计算链是实际关节角→正运动学→投影→线/圆弧连续截面→保持局部长度的内外弯调整→机械模块长度归一化→Yamada曲率积分。原C#源码只读编译为一次几何对照，不是运行依赖。8个输入覆盖起始关节奇偶与4个相位；Python与参考同规则几何一致，另核对已有MuJoCo轨迹中的实际骨架。

开放圆弧需要三个明确改动：

1. 短圆弧采用主动骨架的拟合平面估计截面方向，前后被动边界只提供曲线相接，不决定拟合平面。原pitch-variance估计器保留用于移植核对。这个方向是身体的局部几何估计，不保证等于真实管轴。
2. 取消原D规则将直段/外弯强制改为内弯小圆弧。直段保持零曲率，外弯保持符号；避免把开放圆弧持续改造成包围。
3. 不引入原全螺旋的固定螺距角。保留Step1共同滚动相位、零空间扭转参考，并加入参考校准、有限反馈权重及全段开放约束。这是面向局部圆弧的扩展，不是原全螺旋控制原样复现。

原文式(23)印刷形式与图示收紧方向存在歧义。本实现按参考代码的物理方向：固定长度的圆弧半径除以`1+K`、转角乘以`1+K`。没有作者勘误证据，不把这个解释写成已确认的论文更正。

## 控制计算

输入只有完整实测关节角、已知连杆长度、固定使能掩码与滚动相位。没有管径输入、接触力输入、根部位姿牵引、在线窗口扩大或步态切换。

每50 ms截取局部骨架，包含进入/离开使能区的各一个边界连杆；内部主动骨架进行SVD平面拟合。投影方向沿历史保持符号和基方向连续，再建立有符号连续线圆弧。各线圆弧按所属机械模块共同缩放，避免只缩放圆弧而遗漏直线。

在固定模块弧长上，内部圆弧转角乘`1+K`，首末主动关节的增益减半；边界被动模块不施加增益。外弯不翻成内弯。Yamada在相邻两根连杆的完整长度上积分曲率；在零空间扭转情况下，奇数关节乘`cos(phase)`，偶数关节乘`direction*sin(phase)`，对应Step1的全局关节编号。

同时建立同一相位的名义参考：只替换主动关节为Step1目标，被动关节继续使用实测值。设`Y`为截面重建及积分，候选主动目标为：

```text
q_goal = q_reference + yielding × [Y(actual_shape, K) − Y(reference_shape, 0)]
```

此差分消除离散曲线逆变换在参考形态上的系统误差。`K=0`仍包含实际形状反馈，不能把它当成基础开环；基础对照直接使用Step1。`yielding<1`使反馈有名义恢复参考，而不是完全复制每次已收紧的实际形状。

候选目标先限位，再由正运动学检查连续截面绝对转角总和与开口；若不合格，以8步二分减小反馈修正量，不能通过使能被动关节满足约束。参考本身不合格时报告`reference constraint infeasible`，该运行不能通过验收。

随后使用一阶滤波和关节目标速度限制，由限矩PD仅驱动固定主动关节。约束报告中的目标是滤波前候选；另对保存的实际下发目标重建几何，确认本批次滤波后也未违反开放约束，最大187.45°、最小开口比0.5518。几何更新之间保持当前候选，相位在下一次几何更新时重新积分。

## 运行与复盘

在仓库根目录先执行`conda activate mujoco`，沿用参考项目的已有环境。以下为当前运行命令；历史报告仍保留实际使用的原环境记录。

```powershell
# 每条命令只运行一个场景。空格保持/恢复相位，E切换K=0/.02，R反向
python codes/Rolling_Arc_Section_Mujoco.py --scene taper_true90 --start-x -.35 --duration 75

# 最长120秒；全身出弯后观察3周期即结束。另存输出，避免覆盖本批次证据
python -X utf8 validation/fixed_section_experiment.py --scene taper_true90 --label my_taper90 --start -.35 --duration 120 --exit-cycles 3 --output validation/results/my_section

# 重放原结果，透明管道只改善视线遮挡，不改变碰撞或实际状态
python -X utf8 validation/render_fixed_section.py --labels r5_taper90 r5_elbow90 --video
python -X utf8 validation/audit_fixed_section.py
```

实测状态、目标、掩码、曲线、轴、相位、力矩和评价量保存在`validation/reports/fixed_section/*_trace.npz`；每次判断见同名JSON。视频按100 ms保存态10 fps回放，视频本身不进入Git；原始状态及生成脚本进入Git。摄像机沿管路跟随，侧视与端视并列。新入口的交互键位未通过人工GUI操作验证，已检查CLI可加载；动力学控制核心已由实验入口运行。

对连续90°急弯，最近管轴框架在拐角处相差90°，因此不能定义同一个平直管截面的包绕角。原自动检查保留`passed=false`，有效区间包绕在允许带内；无效区间的实际局部连续截面转角164.89°–185.90°、开口比≥0.5571、平面拟合误差最大8.35 mm，分镜保持开放，支持“未见螺旋收紧”的判断，但不替代原验收量。详细原始角跳变见`r5_elbow90_geometry_audit.json`。

本批次已经完成约定实验，不自动追加新轮次。若后续需要将急弯纳入统一数值验收，应先定义弯角处的分段/三维开放形态指标，再冻结门槛；不能事后降低可观测性要求。局部窗口迁移和实机迁移均等待用户决定。
