# 双侧悬垂端维护重力方向：显示实现

2026-10-13完成。本轮只改显示，现有顺应控制、自动位置/数量选择和热键不使用这个新估计器。仿真已验证，未连接实机。测试计划见[冻结计划](双侧重力预览验证计划.md)，数字与完整过程见[实验复盘](../validation/reports/gravity_preview/README.md)。

## 使用

仍在已有`mujoco`环境直接运行`codes/Rolling_Arc_Debug_Mujoco.py`或单文件`codes/Rolling_Arc_Real.py`。仿真除真实场景窗口外，自动打开与实机相同的角度重建窗口。

- 默认按估计重力对齐，头部仍是位置原点。窗口右上角 **Gravity / Head** 切换重力对齐/头部坐标；鼠标旋转观察。
- 实测骨架、目标虚线、使能颜色与算法候选保持原有含义。两条骨架使用同一个刚性旋转，失能段目标沿用实测角。
- “双侧融合”表示几何一致性通过，不代表测到了真实重力。“单侧补充（降级）”“双侧冲突，保留方向”“无可信悬垂段，保留方向”“反馈陈旧”分别提示退化原因。尚无方向时退回头部坐标。
- 实机顶部`PREVIEW_GRAVITY_ALIGN=False`可将默认视图改为头部坐标，`SHOW_PREVIEW=False`关闭预览；仿真顶部`SHOW_SHAPE_PREVIEW=False`关闭附加重建窗口。
- 关闭预览不停止机器人。预览进程不连接串口、不发电机指令；启动未接管时实际扭矩状态仍未知。重力解释以选定窗口外关节确实失能、悬垂且未被托住为条件。

## 方法和输入边界

输入仅为全身实测关节角、机械尺寸、当前窗口及反馈采样时间。两侧各取最远端最多4根、至少3根连杆，统一为“从圆弧走向自由端”的方向；不是把头到尾的两个相反方向直接平均。

直线度至少0.98，方向还应朝向圆弧开口。长度、直线度及端部自身形变影响权重；两侧方向相差不超过25°时共同融合，单侧不合格则降级使用另一侧，两侧冲突则保留历史并明确标记。仅新反馈更新，重复绘图不产生新观测。

历史方向通过合格端部的连杆坐标变化作条件性传递，再以0.4 s时间尺度和每秒30°的校正速率约束向当前融合方向修正。30°/s限制的是相对预测的校正，不是整个画面的世界角速度。超过0.8 s反馈间隔后放弃旧端部坐标传递，重新缓慢获取。

**关节角不能精确观测整条蛇的刚体转动。** 上述历史传递依赖端部近似保持重力方向；两端共同摆动时，角度无法独立验证这项假设。双侧冲突时保留的是头部坐标中的历史方向，不是有外部姿态传感器支持的世界固定方向。画面仅估计上下，水平朝向采用显示约定，世界位置也未知。

模块为`snake_control/gravity_preview.py`；`tools/build_real_gravity_preview.py`将同一声明嵌入实机文件，保持复制一份Python即可使用。实机文件第6部分负责预览，原控制观察器未替换。MuJoCo根位姿、真实重力和接触只在离线复盘中评价，未输入显示估计器或默认控制器。

## 当前结论

功能达到本轮显示使用范围：可更新、切换、降级和恢复，骨架长度保持，无翻转或控制写入。**“维护历史一定比瞬时双侧融合更平滑”没有得到本轮证据支持**，两段记录的方向变化95分位反而略高；滤波有滞后。外力使一侧仍很直但方向偏斜时，融合也会偏，25°冲突阈值不能识别所有扰动。

因此停止增加仿真测试，等待用户实测。若实测出现明确问题，下一项最小验证是对对应角度记录离线重放；不据本轮结果宣称绝对姿态重建、完全消抖或实机已通过。
