# 圆弧滚动实机调试

运行 `codes/Rolling_Arc_Real.py`，Python 直接通过串口向真实舵机发送目标和使能命令。入口不需要 MuJoCo、EXE、TCP 服务或其他调试窗口，也不导入本仓库其他 Python 文件。只需 Python、pyserial 和 pynput。本机已安装 pyserial 3.5、pynput 1.8.2。

## 启动

在仓库根目录执行：

```powershell
# 本机已安装；新环境执行一次
py -3.12 -m pip install -r requirements-real.txt

# 默认真实串口，端口来自原设备档案
py -3.12 codes/Rolling_Arc_Real.py --port COM9 --log logs/rolling_arc_real.jsonl

# 不用热键时，在控制台输入相同命令并回车
py -3.12 codes/Rolling_Arc_Real.py --port COM9 --no-hotkeys
```

启动仅打开串口，不自动改变舵机扭矩或姿态。此时脚本尚未接管，不代表实机原本已经失能。Ctrl+U / `apply` 形成基础圆弧，或 Ctrl+E / `compliance` 从已有受支持姿态接管。真实运行期间，这份脚本直接占用串口，原可视化 EXE 等其他串口程序应关闭。

基础 `apply` 默认使能 J8–J13，其他 14 个舵机写入失能命令，逐 ID 读回全部使能状态。顺应性模式使能范围随支撑观测改变；位置报文只包含当前有效掩码内舵机。脚本使用原档案逐舵机零位，COM9/115200 是参考档案值，不是本轮对当前连接状态的检测结果。

## 调试操作

键位参考 `Adaptive_Pole_Climbing_Real.py` 的 Ctrl+字母操作，移除了 F 键。热键全局有效，按住不放不会自动累计单步。Ctrl+空格暂停，普通空格不绑定，避免输入一行多个参数时误触暂停。

| 热键 | 控制台命令 | 行为 |
| --- | --- | --- |
| Ctrl+U | `apply` / `arm` | 读取窗口内当前位置，预置当前位置目标，设置驱动参数，使能局部，缓慢形成相位 0 圆弧；完成后保持 |
| Ctrl+J / Ctrl+H | `step` / `back` | 相位增加/减小一个步长，平滑发送，完成后保持；形成阶段输入会等待形成及静置结束 |
| Ctrl+G | `run` / `pause` | 连续滚动/暂停切换；`run` 明确开始，`pause` 明确暂停 |
| Ctrl+E | `compliance` | 顺应性开/关，从实测姿态接管，保留当前相位；接入后默认保持相位 |
| Ctrl+空格 | `pause` | 停止相位推进；基础模式冻结目标，顺应性模式继续顺应调整 |
| Ctrl+N | `hold` | 保持并重发最近目标，取消未完成的单步 |
| Ctrl+T | `reverse` | 反转连续滚动的相位推进方向，操作本身不改变目标姿态 |
| Ctrl+- / Ctrl+= | `delta-` / `delta+` | 单步相位步长减半/加倍，快捷调整范围 0.01–0.6 rad |
| Ctrl+上 / 下 | `amplitude_up` / `amplitude_down` | 幅值 ±2°，保持当前相位，缓慢调整构型 |
| Ctrl+右 / 左 | `omega_up` / `omega_down` | 角频率 ±0.05 rad/s |
| Ctrl+K | `status` | 读取全部 20 个实际角和原始反馈，显示控制器角及原始负载 |
| Ctrl+X | `release` | 全部失能并逐 ID 读回；会失去主动支撑，与暂停不同 |
| Ctrl+Q | `quit` / `exit` | 退出；已经接管或执行释放后，再次发送全失能并读回 |
| — | `help` | 打印调试操作 |

典型操作：启动 → Ctrl+U 形成圆弧 → 等待“保持”且静置结束 → Ctrl+J/H 单步观察 → Ctrl+G 连续滚动 → Ctrl+空格暂停 → Ctrl+X 释放。

相位 0 下奇数主动关节为 60°、偶数为 0°。从零位形成该目标时，软件目标速度上限为 15°/s，约需 4 s，再静置 2 s；不同实测起点需要不同时间。这是目标形成过程，不是对实机到位时间的测量。若中途暂停，后续 `run` / `step` 会先平滑恢复当前相位圆弧，再滚动。重复 `apply` 在已经接管时不重置相位；需要重新形成时先释放，再 `apply`。

## 常改哪里

全部在同一 Python 文件中，按注释分为八段。基本参数和顺应性调试参数均集中在第 1 段，公式在第 2/3 段。

| 位置 | 可修改内容 |
| --- | --- |
| `1. 经常修改的实验参数` | 串口、J8–J13 窗口、幅值、角频率、单步增量、形成速度、舵机速度/力矩限制/加速度 |
| `SERVO_IDS / ZERO_RAW / SERVO_DIRECTION` | 实机 ID、校准零位与安装方向，顺序为 J1..J20 |
| `MODEL_TO_SERVO_SIGN` | 控制器角到协议角的坐标符号；当前奇数 +1、偶数 -1，来自原项目 |
| `joint_angles_deg()` | 圆弧公式：奇数 `A*cos(phi)`，偶数 `A*sin(phi)`；返回度，输入相位为 rad |
| `SlidingArcOptions` / `SlidingArcCompliance.update()` | 实测幅值让顺、支撑迟滞、窗口迁移与交接；仿真直接使用同一实现 |
| `RollingArcController.support_observations()` | 原始负载+姿态估计或人工支撑段；实机接触判别主要在这里调整 |
| `angle_to_raw()` / `raw_to_angle()` | 校准与反向换算；原始位置范围 0..4095 |
| `FeetechBus` | 串口报文、读反馈和失能操作，调步态时通常不用改 |
| `RollingArcController.command()` / `tick()` | 功能切换和逐帧发送；热键线程只排队，串口由主循环统一操作 |

也可以运行中输入参数，不需要重启：

```text
amplitude=58 omega=0.5 delta=0.05
pause
step
back
release
window=7:14
apply
```

一整行参数先验证再更新，无效输入不会留下部分改动。基础模式幅值改变保持相位，以形成速度调整；顺应性模式修改幅值上限后由核心平滑调整。`window` 是基础/初始窗口，只能释放后改；顺应性模式根据 `support` 观测动态更新窗口。修改窗口、幅值或公式后，原仿真通过结论需要重新评估。

## Step2 顺应性操作

常规圆弧实验：Ctrl+U 形成 → 静置结束 → Ctrl+K 观察原始负载 → Ctrl+E 接入顺应性 → Ctrl+J/H 单步 → Ctrl+G 连续。Ctrl+E 接入保持当前相位，不跳回 0；再次按下返回基础模式并保持，下一次滚动会限速恢复统一幅值。

已有搭管姿态：不按 Ctrl+U，先确认机器人已受管道支撑，输入 `support=auto` 或实际支撑范围，直接 Ctrl+E。从实际角拟合相位，预置实际角再使能，不先拉成默认中央圆弧。`support` 指实际支撑候选，控制器会选择连通段并加边界关节；使能窗口不等于每一个连杆都直接接触。

下面的支撑范围应按实物修改：

```text
support=9:11
compliance
step
pause
gain=0.02 load=40 omega=0.5
run
hold
support=auto
status
```

默认 auto 要求原始负载绝对值至少 40，且局部实测奇偶角包络至少 20°。这只是负载+姿态估计，无法区分管道支持、重力、摩擦或卡死；失能舵机的原始负载尤其不能可靠反映支持力。因此仿真使用真实碰撞力，实机自动支撑判别与跨入原失能区域的可靠性需要你验证。没有观测时拒绝接管；运行时支撑观测缺失 0.5 s 停止相位。不能将目前的离线检查写成实机接触识别成功。

人工 `support=首:尾` 始终信任指定区域，需根据实际搭管随时更新；它没有真实接触丢失检测。运行中改变 support 后，新候选持续一段时间才移窗；新舵机先立即重读/预置实际位置，再开扭矩，旧舵机让向实测姿态并在权重归零后关闭。目标窗口默认 6–12 关节，交接时是新旧窗口临时并集，其余关节明确失能。当前窗口足够覆盖支撑时不会频繁重定位。

最常调整的顶部参数：`COMPLIANCE_GAIN`、`MIN_COMPLIANCE_AMPLITUDE_DEG`、`CURVATURE_FILTER_S`、`MIN/MAX_WINDOW_JOINTS`、`WINDOW_GUARD_JOINTS`、`WINDOW_DWELL_S`、`WINDOW_TRANSFER_S`、`SUPPORT_LOAD_THRESHOLD_RAW`、`SUPPORT_CURVATURE_THRESHOLD_DEG`。通常先调原始负载阈值与支撑段，再调整增益；不要把 `load=40` 当作 40 N。详见 [Step2 方法与验证边界](Step2设计说明.md)。

`MAX_TARGET_RATE_DEG_S=45` 限制软件目标角速度；对默认正弦公式要求 `amplitude*omega <= 45`。`SERVO_SPEED_RAW=800`、`TORQUE_LIMIT_RAW=300`、`ACCELERATION_RAW=20` 是设备寄存器原始值，不能分别直接当成 °/s、N·m 或 rad/s²。实际内部位置环由舵机执行，仿真的 PD 增益和 2.355 N·m 上限没有被写入实机。真实失能关节的机械阻力也未由本轮测量。

## 反馈、记录与离线检查

基础模式每秒读取窗口内位置。顺应性模式以 0.2 s 周期读取全部 20 个舵机 56..70 寄存器块：位置、原始负载、原始电流、电压、温度、状态和运动标记；`status` 同样读取全部。该周期是请求周期，真实总线速度需要实测，目标发送仍至多 50 Hz，不追赶阻塞漏帧。全量反馈超过 0.8 s 未更新、错误应答、协议校验失败、读取超时、串口写失败或使能读回不一致会结束并尝试全部失能。退出读回成功才打印确认；断连后软件无法保证最后失能命令送达。

日志 JSONL 包含时间、相位、动态掩码、发送目标、最近实测角和 `feedback_time_s`，以及顺应性窗口、幅值、支撑来源、人工支撑范围、原始反馈。`servo_feedback_raw` 的索引从 0 开始；显示/使能窗口的关节编号从 1 开始。反馈可能早于该行目标，不能把每行当成一次新实测。原始负载/电流没有力矩和电流单位标定，不记录可靠功率、电能或真实管道进度。

全量反馈按扫描开始时间计龄；若一次扫读超过 0.8 s 会直接停止，避免把扫描结束误作 20 个舵机同时获得新反馈。`command_phase_rad` 是本次目标使用的相位，`phase_rad` 在顺应性滚动时可能已推进到下一控制帧。

离线模式走同一协议和控制路径，但位置反馈由内存串口直接回显目标，不包含机器人动力学。

```powershell
# 交互演练；不会打开 COM 口
py -3.12 codes/Rolling_Arc_Real.py --dry-run

# 批量离线检查：形成 -> 静置 -> 连续 -> 退出失能
py -3.12 -X utf8 codes/Rolling_Arc_Real.py --dry-run --no-hotkeys --no-console --auto --fast --duration 12 --log validation/results/real_controller/dry_run.jsonl

# 形成 -> 接入同一顺应性核心 -> 连续 -> 退出；人工支撑只是离线输入
py -3.12 -X utf8 codes/Rolling_Arc_Real.py --dry-run --no-hotkeys --no-console --auto --compliance --support 9:11 --fast --duration 15 --log validation/results/step2_real_dry_run.jsonl

# 必要的控制与协议检查；没有真实串口访问
py -3.12 -X utf8 -m unittest discover -s validation -p "test_*.py" -v
```

已完成单文件实机程序、Step2 共享核心移植和 24 项必要检查；实机 Step2 新增检查覆盖偏置姿态接管、带符号原始反馈、新关节预置及使能交接、相位保持、无支撑拒绝接管和陈旧反馈停止。未连接真实机器人。历史记录在 `validation/reports/real_controller/`，Step2 记录在 `validation/reports/step2/real_port_summary.json`。
