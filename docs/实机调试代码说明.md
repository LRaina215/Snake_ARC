# 圆弧滚动实机调试

运行 `codes/Rolling_Arc_Real.py`，Python 直接通过串口向真实舵机发送目标和使能命令。入口不需要 MuJoCo、EXE、TCP 服务或其他调试窗口，也不导入本仓库其他 Python 文件。只需 Python、pyserial 和 pynput。本机已安装 pyserial 3.5、pynput 1.8.2。

## 启动

在仓库根目录执行：

```powershell
# 本机已安装；新环境执行一次
py -3.12 -m pip install -r requirements-real.txt

# 默认真实串口，端口来自原设备档案
py -3.12 codes/Rolling_Arc_Real.py --port COM9 --log logs/rolling_arc_real.jsonl

# 不用热键时，在控制台输入相同命令并回车
py -3.12 codes/Rolling_Arc_Real.py --port COM9 --no-hotkeys
```

启动仅打开串口，不自动改变舵机扭矩或姿态。此时脚本尚未接管，不代表实机原本已经失能。按 Ctrl+U / 输入 `apply` 后才开始实验。真实运行期间，这份脚本直接占用串口，原可视化 EXE 等其他串口程序应关闭。

默认 J8–J13 使能，其他 14 个舵机明确写入失能命令，并逐 ID 读回全部使能状态。目标位置报文只包含窗口内舵机。脚本使用原档案的逐舵机零位，而不是统一零位 2048；COM9/115200 是参考档案值，不是本轮对当前连接状态的检测结果。

## 调试操作

键位参考 `Adaptive_Pole_Climbing_Real.py` 的 Ctrl+字母操作，移除了 F 键。热键全局有效，按住不放不会自动累计单步。Ctrl+空格暂停，普通空格不绑定，避免输入一行多个参数时误触暂停。

| 热键 | 控制台命令 | 行为 |
| --- | --- | --- |
| Ctrl+U | `apply` / `arm` | 读取窗口内当前位置，预置当前位置目标，设置驱动参数，使能局部，缓慢形成相位 0 圆弧；完成后保持 |
| Ctrl+J / Ctrl+H | `step` / `back` | 相位增加/减小一个步长，平滑发送，完成后保持；形成阶段输入会等待形成及静置结束 |
| Ctrl+G | `run` / `pause` | 连续滚动/暂停切换；`run` 明确开始，`pause` 明确暂停 |
| Ctrl+空格 | `pause` | 立即停止相位推进及形成过程，保持最近已发目标 |
| Ctrl+N | `hold` | 保持并重发最近目标，取消未完成的单步 |
| Ctrl+T | `reverse` | 反转连续滚动的相位推进方向，操作本身不改变目标姿态 |
| Ctrl+- / Ctrl+= | `delta-` / `delta+` | 单步相位步长减半/加倍，快捷调整范围 0.01–0.6 rad |
| Ctrl+上 / 下 | `amplitude_up` / `amplitude_down` | 幅值 ±2°，保持当前相位，缓慢调整构型 |
| Ctrl+右 / 左 | `omega_up` / `omega_down` | 角频率 ±0.05 rad/s |
| Ctrl+K | `status` | 读取全部 20 个实际关节角，显示为控制器坐标 |
| Ctrl+X | `release` | 全部失能并逐 ID 读回；会失去主动支撑，与暂停不同 |
| Ctrl+Q | `quit` / `exit` | 退出；已经接管或执行释放后，再次发送全失能并读回 |
| — | `help` | 打印调试操作 |

典型操作：启动 → Ctrl+U 形成圆弧 → 等待“保持”且静置结束 → Ctrl+J/H 单步观察 → Ctrl+G 连续滚动 → Ctrl+空格暂停 → Ctrl+X 释放。

相位 0 下奇数主动关节为 60°、偶数为 0°。从零位形成该目标时，软件目标速度上限为 15°/s，约需 4 s，再静置 2 s；不同实测起点需要不同时间。这是目标形成过程，不是对实机到位时间的测量。若中途暂停，后续 `run` / `step` 会先平滑恢复当前相位圆弧，再滚动。重复 `apply` 在已经接管时不重置相位；需要重新形成时先释放，再 `apply`。

## 常改哪里

全部在同一 Python 文件中，按注释分为七段。通常只需改前两段。

| 位置 | 可修改内容 |
| --- | --- |
| `1. 经常修改的实验参数` | 串口、J8–J13 窗口、幅值、角频率、单步增量、形成速度、舵机速度/力矩限制/加速度 |
| `SERVO_IDS / ZERO_RAW / SERVO_DIRECTION` | 实机 ID、校准零位与安装方向，顺序为 J1..J20 |
| `MODEL_TO_SERVO_SIGN` | 控制器角到协议角的坐标符号；当前奇数 +1、偶数 -1，来自原项目 |
| `joint_angles_deg()` | 圆弧公式：奇数 `A*cos(phi)`，偶数 `A*sin(phi)`；返回度，输入相位为 rad |
| `angle_to_raw()` / `raw_to_angle()` | 校准与反向换算；原始位置范围 0..4095 |
| `FeetechBus` | 串口报文、读反馈和失能操作，调步态时通常不用改 |
| `RollingArcController.command()` / `tick()` | 功能切换和逐帧发送；热键线程只排队，串口由主循环统一操作 |

也可以运行中输入参数，不需要重启：

```text
amplitude=58 omega=0.5 delta=0.05
pause
step
back
release
window=7:14
apply
```

一整行参数先验证再更新，无效输入不会留下部分改动。幅值改变保持相位，并以形成速度平滑调整；连续模式会先等待调整和静置完成再继续。窗口只有释放后能改，属于人工指定的固定局部区域；本阶段未实现自动接触识别、滑动窗口和顺应性。修改窗口、幅值或公式后，原仿真通过结论需要重新评估。

`MAX_TARGET_RATE_DEG_S=45` 限制软件目标角速度；对默认正弦公式要求 `amplitude*omega <= 45`。`SERVO_SPEED_RAW=800`、`TORQUE_LIMIT_RAW=300`、`ACCELERATION_RAW=20` 是设备寄存器原始值，不能分别直接当成 °/s、N·m 或 rad/s²。实际内部位置环由舵机执行，仿真的 PD 增益和 2.355 N·m 上限没有被写入实机。真实失能关节的机械阻力也未由本轮测量。

## 反馈、记录与离线检查

运行中每秒读取窗口内实际位置，`status` 读取全部位置。错误应答、协议校验失败、读取超时、串口写入失败或使能读回不一致会结束控制，并尝试全部失能。退出读回成功才打印“全部舵机失能已读回确认”；串口已断连时，软件无法保证最后一条失能指令送达。

日志使用 JSONL，包含软件时间、相位、使能窗口、实际发送目标、最近实测角及其 `feedback_time_s`。最近反馈可能早于该行目标时间，不能把每行记录都当成一次新实测；当前日志不测量负载、电流、功率或管道进度。

离线模式走同一协议和控制路径，但位置反馈由内存串口直接回显目标，不包含机器人动力学。

```powershell
# 交互演练；不会打开 COM 口
py -3.12 codes/Rolling_Arc_Real.py --dry-run

# 批量离线检查：形成 -> 静置 -> 连续 -> 退出失能
py -3.12 -X utf8 codes/Rolling_Arc_Real.py --dry-run --no-hotkeys --no-console --auto --fast --duration 12 --log validation/results/real_controller/dry_run.jsonl

# 必要的控制与协议检查；没有真实串口访问
py -3.12 -X utf8 -m unittest discover -s validation -p "test_*.py" -v
```

本轮已完成单文件实机程序、离线协议及控制检查，并在 Windows 上验证全局监听器能启动和退出；未连接真实机器人，未完成真实直管/弯管通过实验。验证记录见 `validation/reports/real_controller/README.md`。
