# 主动两侧长度调整研究原型

2026-10-14，第一轮三次比较、第二轮一次返回残差修复已完成，不更新实机/热键。结果和完整记录见[本轮复盘](../validation/reports/active_transfer/README.md)，假设/数量上限见[实验前计划](主动两侧长度调整实验计划.md)及[第二轮单例计划](../validation/reports/active_transfer/feedback_return_plan.md)。暂停滚动搬弧的动作能力成立，闭环修复后末态冠部返回误差由.410降到.105关节；全过程旧端点规则仍有超限，不称研究整体通过。松弧滚动的方向可控与稳住阶段未通过。不能把研究原型当作已验证的实机功能。

## 代码与反馈边界

`snake_control/active_arc_transfer.py`的`ActiveArcTransfer`只有全关节角、采样与控制时间输入；机械长度和动作参数构造时固定。输出`target_rad`与独立布尔`enabled`掩码。没有MuJoCo、接触、管径、root、世界重力或真实力矩接口。

不使用顺应性：圆弧目标按预设幅值和相位生成，实测角只参与新进入关节预置、退出角确认、条件性冠部观察和时钟校验。`TransferOptions`集中保存幅值、建立时间、搬移时间、方向、退出角、观察时间与可选往复参数，方便将来单文件移植和DIY修改。

适配器`validation/active_transfer_experiment.py`直接复用`ArcSimulation`、`LocalMotorDrive`与现有直管模型。20ms生成目标、200ms模拟读角、1ms物理步。窗口外主动矩严格0；参考模型的被动阻尼和惯量继续存在，未辨识为真实断电舵机模型。

## 两条动作

方向一状态：建立稳定圆弧→降低幅值放松、持续滚动→角度冠部偏移满足方向/持续门槛→跟随搬移并恢复稳定模板→结束。真实两侧长度不进入控制器。当前45°、35°病例都未进入恢复稳住阶段，后半段仅实现了软件接口、没有物理通过证据。不能因为35°更明显就说指定方向控制完成。

方向二状态：建立→相邻窗口并集→5s平滑角度关键帧→新角反馈确认退出关节≤12°→退出失能→3s观察→反向搬移→观察结束。本轮J8–J13→J7–J12→J8–J13，稳定6、过渡7。进入关节先用实测角预置，共享关节保持连续；目标按45°/s上限生成，不向失能关节发恢复目标。

关键帧采用旧/新圆弧目标的smoothstep插值，重叠期间旧边界减弯、新边界增弯；按全局奇偶轴保留cos/sin关系。选择两族非零的phase=.7，动作期间不推进滚动相位。没有名义恢复项，也没有实测半径更新。若需辅助可启用小幅相位往复；本轮没有卡住，未启用和验证该分支。

`completed`只表示预设序列执行结束，**不是实际长度目标验收通过**；snapshot明确记录其含义。首版返回只回原目标和掩码，存在约.41关节/28mm材料重分配残差，第一步约.71冠部关节/47mm净材料转移，不能称精确1关节。

第二轮通过`TransferOptions.feedback_align=True`在交接后增加位置修正：以初始实测冠部减1及返回初始值为目标，积分更新首尾弯曲分配偏置，限±.4，每个奇偶轴族总角预算不变。达到±.12关节的角度代理误差并持续.4s后观察3s；最长修正12s。反馈没有管径或接触，曲率分配可略不均，不再要求各关节等角。末态真实冠部残差.105关节，实际两侧残差+7.8/-9.7 mm；去程观察末态偏移1.193关节，仍有达到目标后继续变化的问题。当前只证明这个姿态中的有限精度，不证明任意场景精确位置控制。

## 观察与评价

冠部观察沿用实测骨架/截面和合格悬垂端的条件性向下估计，不把它当作IMU。固定相位例误差较小，滚动例仍有最大约.56关节偏差；既有双端历史滤波离线没有改善，未接入。

仿真评价另保存世界最高带的身体材料坐标、按管轴中心高度穿越点截取的两侧悬垂长度、支撑连杆分布。后者是明确的几何评价口径，并非由舵机直接量到的接触边界；两侧长度都变短时，需区分拱起长度增长和材料转移。最高点变化也不自动等于支撑位置变化。

保留历史使能区端点绕管角，并记录实测曲线总转角与开口。并集使能时一个仍近直线的边界段进入统计，会产生绕管角瞬时跳变；不能直接把236°读数解释为圆弧变成螺旋，也不能删去该读数来报严格通过。本轮原150–218°端点规则有超限标记，研究整体形态验收仍未完成。

## 运行与后续移植

已有mujoco环境内，软件检查：`python -X utf8 validation/test_active_transfer.py`。完整记录只读复盘：`python -X utf8 validation/review_active_transfer.py`；第二轮加`--feedback-return`。研究入口`active_transfer_experiment.py loose / transfer`，方向一修复为`loose --repair`，第二轮单例为`transfer --feedback-return`；两轮预算3+1均已用完，重跑需另行明确新批次，不删除历史记录绕过预算。

未来移植复用现有飞特`prepare_enabled`：预置新进入ID、写入并集掩码，公共ID不重新配置，退出条件满足后只关闭旧边界。实机仍应运行现有单文件Python和Ctrl热键，但本轮没有嵌入这些新动作。方向二已补有限精度的实际目标闭环，后续优先让结束观察期间也维持位置反馈，再决定移植；方向一先解决方向引导与支撑区域确认，再验证停止滑移/恢复模板。
