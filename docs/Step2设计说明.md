## 实现及范围

保留 Step1 奇偶关节正交滚动公式、全局关节编号及相位。只修改局部幅值与使能范围；连续 L 型急弯全程直接滚动通过。控制器只接收实测关节角、支撑观测和时间，不读取管道中心线、半径、路程或机器人根部位姿。

这是基于实测关节角的**位置目标让顺控制**，不是接触力闭环、力矩导纳，也不是参考项目完整的 Yamada 曲线重构。仿真 PD 和舵机内部位置环分别执行目标，二者不被当作同一种物理执行器。

控制核心位于 `codes/Rolling_Arc_Real.py` 的第 3 段；`snake_control/arc_compliance.py` 直接导出它。这样仿真和实机使用同一套公式，而实机复制单个 Python 文件仍能运行。仿真接触提取与物理步进在 `snake_control/adaptive_simulation.py`，实机反馈适配在 `RollingArcController`。

## 局部幅值让顺

对当前有效关节 i，找到当前窗口内最近的异奇偶关节 j，用实测角构造幅值代理：

\[
E_i=\sqrt{q_i^2+q_j^2},\quad
B_i=\mathrm{clip}((1+g)E_i,A_{min},A_{max})
\]

\[
A_i\leftarrow A_i+(1-e^{-\Delta t/\tau})(B_i-A_i)
\]

角度单位均为度；默认 g=0.02、τ=0.5 s、幅值范围 25°–60°。E 是曲率幅值代理，不能直接视为管道半径或物理曲率。接触使实际弯曲减小时，目标幅值随之减小。虽然每次使用实测角，实际角也会跟随所发目标：当 E 接近当前幅值时，乘以 1.02 仍会让目标缓慢增大。因此“使用实测角”并没有排除闭环中的自增强；60°上限只限制单关节幅值，不能限制整段包绕角。这个问题需要修正。

目标保持原来的奇偶相位关系：奇数 `A_i*cos(phi)`、偶数 `A_i*sin(phi)`。以 45°/s 限速输出。新接管从当前实测角开始；已有控制切换保留相位及最近目标。对全新已有搭管姿态，用选定支撑窗口内奇、偶实测角的均值拟合初始相位，不拉回相位零。

这套幅值控制没有显式重构三维管轴或每一处包绕半径。当前变径结果仅说明原型能在这些条件下维持支撑并推进，不能据此认定它保持了目标圆弧形态或已解决任意曲率、直径或姿态。

## 支撑观测与窗口

MuJoCo 适配层读取机器人与管道的真实碰撞力，将接触坐标系的力转到世界系，取作用于机器人上的正向竖直分量。同一连杆的反力累加，映射到相邻关节；超过 0.5 N 记为支撑候选。地面接触不作为管道支撑。力变换方向参考 [MuJoCo 接触力约定](https://mujoco.readthedocs.io/en/2.3.1/computation.html)，使用本机 MuJoCo 3.3.0 API。

| 机制 | 默认设置与作用 |
| --- | --- |
| 观测锁存 | 连续 0.12 s 记为支撑，连续缺失 0.8 s 才清除 |
| 支撑连通段 | 相邻候选间隔最多 2 个关节；不把远处孤立碰撞直接连成全身窗口 |
| 初始选择 | 选择总支撑最强的一段，不预设必须是 J8–J13 |
| 后续选择 | 选择距当前窗口最近的一段，避免跳到远端偶然碰撞 |
| 目标窗口宽度 | 支撑跨度加两侧各 2 个边界关节，偶数宽度，6–12 个关节 |
| 保持条件 | 支撑仍被当前窗口覆盖时保持；不会为了居中而反复移动 |
| 迁移条件 | 支撑移出当前窗口，新候选持续 0.6 s 后接管 |
| 交接 | 0.8 s 新旧目标渐变，暂停相位 1.2 s（含 0.4 s 整定） |
| 支撑丢失 | 无新支撑观测持续 0.5 s 停止相位推进，保持局部控制 |

窗口内包含支撑相邻关节和必要的边界关节，**不要求每一个使能关节对应的连杆都直接接触**。接触力通过整段连杆传递；只开直接接触处容易让顶部构型散开。这是对规划中“仅受力关节使能”的实施解释。

扩大窗口时，先按旧/新宽度比缩小幅值，近似保持累计弯曲量，随后继续由实测包络更新；这不是精确的包绕半径不变量。目标窗口内权重逐渐变为 1，退出关节逐渐让向实测姿态，权重归零后才真正失能。交接期间有效掩码为新旧窗口的暂时并集，可能大于目标窗口宽度；其余关节主动力矩始终为零。实机对新关节先重读实际角、预置目标，再开扭矩；退出关节明确写入扭矩关闭并读回。

已经足够的窗口不主动缩小。开发时观察到，按接触中心频繁扩大/平移会导致后部搭管跌落；最终改用上述保持规则。当前方案优先维持支撑，尚未优化使能数或能量。

## 仿真验收

机器人及执行参数沿用 Step1：20 关节、连杆 64.5 mm、主动 PD 127/1、限矩 2.355 N·m、被动阻尼 1.5。步进 1 ms，控制 20 ms，记录 100 ms。变径碰撞网格原样复用参考仓库，直径 113→163 mm，过渡轴长约 16.58 mm；名为 `taper_bend90` 的复用场景实际是在变径后接水平 **45°** 柔弯，中心线弯曲半径 300 mm。此前报告将文件名当作几何依据，错误写成 90°。单独的 Step1/Step2 `bend90` 场景仍为 90°。

普通管道、两种变径、前后偏置、非零相位切换和已有不对称姿态接管共 10 个案例通过了旧的推进/支撑/失能/限矩检查。**旧检查缺少开放圆弧形态，不能视为完整 Step2 通过。** 另有 5 个固定窗口 Step1 对照。结果、参数与原始状态见 [实验记录](../validation/reports/step2/README.md)。窗口迁移不是每个案例都发生；当支撑仍在原窗口内时保持窗口是现有原型的行为。

路程统一使用**整条骨架固定点集合的均值**投影到路线；全身越过障碍使用每个骨架点的最小进度。不会因窗口换了关节就计算出虚假的前进。场景中心线只用于评价。初始搭管后只通过限矩驱动和 `mj_step` 演化，不在运动中施加根部轨迹或重放姿态。

“任意搭管”当前只在有管道支撑、存在可接管弯曲段的条件下实现接管接口；已测 J4–J9、J8–J13、J12–J17 三种起始位置，以及一例非标准已有姿态。没有验证所有随机姿态，未受支撑/几何上无法保持的摆放也不能被这个控制器自动抓到管上。已有姿态入口会等待实际支撑，而非制造支撑信号。

当前基线也能通过这两种变径场景，不能据此证明顺应性改善通过率。普通直管/弯管的推进量差异小于 1.8%；变径弯管机械正功由约 171.05 J 增到 218.01 J（约 +27.46%）。这是仿真执行器机械正功，不是电能；当前结果不支持效率优势。后续应分别控制使能长度、速度与摩擦，做重复实机对比。

## 实机移植与调试

仍只运行 `codes/Rolling_Arc_Real.py`。Ctrl+E 接入/退出顺应性；Ctrl+J/H 单步；Ctrl+G 连续/暂停；Ctrl+空格冻结相位但继续顺应；Ctrl+N 冻结全部已发目标；Ctrl+X 全部失能。Ctrl+E 接入后默认保持，先观察再单步。未保留任何 F 键。

每 0.2 s 读取 20 个舵机的位置与原始负载等反馈，在两次反馈之间以 50 Hz 更新/发送目标。主循环按实际串口速度执行，不补发漏帧；0.8 s 未获得全量新反馈会结束并尝试失能。实际总线采样频率须实机确认。

默认 `support=auto`：原始负载绝对值至少 40，且局部奇偶角包络至少 20°时视为支撑候选。**这只是负载+姿态估计，无法辨别摩擦、重力、卡死与管道支持，也无法可靠观测失能关节上的支持力。** 原始负载/电流没有换算成 N 或 N·m。实机无法直接复制仿真接触真值，自动窗口跨入原来失能区域的可靠性必须单独验证。

若估计不可靠，输入 `support=9:11` 人工给定实际支撑段；输入 `support=auto` 恢复估计。人工模式会一直相信指定支撑，需随实物改变而调整，不能充当接触丢失检测。`gain=0.02 load=40` 可在线调参。当前代码不把几何弯曲自动认定为真实接触；无支撑观测时拒绝接管并提示人工指定。

详细运行顺序和常改位置见 [实机调试说明](实机调试代码说明.md)。24 项必要检查通过，其中新增 Step2 核心 5 项、实机 Step2 6 项；另完成单文件离线串口流程。它们验证控制与协议，不代表真实机械效果。

## 实验复盘与改进方案（2026-10-11）

### 已确认的问题与尚未证明的原因

1. **窗口长度和局部曲率没有持续协调。** 前部变径弯管案例从 J4–J9 扩到 J1–J10。交接时幅值按 6/10 缩小，但之后又回升至约 60°，窗口仍有 10 个关节。90 s 末态在出口直管轴周围的展开包绕角约 294.95°，默认放置末态约 271.85°。它们不是完整一圈，但已经明显偏离开放顶部圆弧目标。
2. **幅值更新存在自增强机制。** `(1+g)*E` 在实际角跟随目标时仍会抬高目标，这是代码可以确认的机制；它对本次收紧现象的贡献还需用冻结相位/固定几何对照分离，不能把所有变形都归因于这一项。
3. **迁移策略只求覆盖支持，缺少形态与退出条件。** 支撑被旧窗口覆盖时不主动缩小，且没有总包绕角、开口或轴向缠绕约束。大管径可能确实需要更长的主动段；不能简单认为“通过变径后必须回到 6 个关节”。需要恢复的是合适的开放形态。
4. **原验收遗漏了研究目标。** 旧的 10 个通过结果并未检查开放形态；基线也能通过当前两种变径。原型尚未证明形态保持、通过率或效率方面的优势。
5. **场景命名错误，实机观测还存在缺口。** 复用变径弯管实际为 45°；仿真真实接触反力与实机原始负载不是同一种观测。特别是失能区域的真实支撑目前无法可靠识别。

上述包绕角仅对已进入出口直段的状态计算：使用实际骨架中窗口覆盖的连杆点，在出口管轴的法平面投影后展开极角，取首尾极角差。它不是将关节角直接相加，也不能把弯管早期状态全部投影到出口轴后作为形态证据。具体数据在 `front_taper_bend90_trace.npz` 和 `taper_bend90_trace.npz`；90 s 末态窗口分别为 J1–J10、J5–J14。

### 优先级一：先建立开放圆弧的验收

- 先重审 Step1 一个完整滚动周期内的实际三维形态，结合开放圆弧目标确定随相位变化的开口和包绕角允许带，并在新控制器调参前锁定验收范围；不能未经验证便把所有相位硬锁为平面 180°圆弧，也不能跟着试验结果放宽标准。
- 增加实际包绕角、开口变化、局部曲率/扭转、轴向跨度及持续收紧趋势。开放滚动允许推进所需的三维扭转，目标是排除大角度包绕和持续绕轴累积，不是将扭转强制为零。
- 直管采用已知管轴评价；弯管采用沿中心线连续变化的局部坐标系，避免固定投影轴造成误判。局部投影不唯一或开口不可测时标明无法评价，不自动判通过。真实管轴和接触只进入评价器，部署控制器不能偷偷读取这些真值。
- 场景核对按实际碰撞几何和中心线进行。保留现有 45°案例作为历史对照，明确兼容 ID `taper_bend90` 的实际含义；另建真正的变径 90°场景并核对网格与元数据。

### 优先级二：修正幅值反馈，再协调窗口

**局部顺应性：** 改成“滚动参考形态 + 有界局部修正”。修正相对于当前相位的参考计算，并带恢复项与形态约束；停止将实测包络乘 1.02 作为会持续抬升的目标。实际角与目标之差同时含有惯性、正常相位滞后、重力和饱和，必须通过对照区分，不能全部解释为管道变径造成的变形。参考项目的实测三维曲线重构可用于估计身体曲率，但身体曲率不等于真实管径，也不自动证明接触。

**窗口迁移：** 先验证固定宽度的平移，再允许按需要扩展。新旧段交接期间保持相位、当前姿态和边界切向连续；新关节从实测角预置，退出段在支持完成转移后失能。扩展时同时求新的开放参考形态，不只做一次幅值缩放后任其回升；支持减少且形态/支撑允许时再收缩，避免永久保留过长窗口。

圆弧近似下弧长、曲率和总转角需要联合约束。6 个关节、60°到 10 个关节、约 36°只可作为初始候选：交替三维旋转不满足简单标量相加，最终必须由实际三维正运动学和动力学检验。连续 L 型急弯仍直接滚动通过，不引入步态转换。

### 优先级三：按能定位原因的顺序做实验

| 顺序 | 实验与固定条件 | 要回答的问题 | 本轮验收重点 |
| --- | --- | --- | --- |
| 1 | 恒径直管，固定窗口，冻结相位但保留顺应更新，观察 30 s；旧/新算法同初态对照 | 无变径时是否仍自行收紧？ | 排除持续幅值/包绕角漂移；区分最初沉降与后续趋势 |
| 2 | 恒径直管，至少一个完整滚动周期；固定窗口，比较 Step1、旧原型、新幅值控制 | 新顺应性是否破坏基础滚动？ | 全周期开放形态、支持与推进；不能只看某个相位 |
| 3 | 恒径直管上的偏置搭管/已有姿态接管，先固定宽度迁移，再加入必要的扩展/收缩；由实际支持变化触发 | 窗口交接自身是否导致闭合或失稳？ | 新段预置、相位连续、主动段曲率协调、退出段真正失能；未触发迁移的运行不算覆盖交接 |
| 4 | 小径→大径→小径直管，同初态/摩擦/限矩；退出变径后仍观察至少 3 个滚动周期 | 扩展和收缩是否保持开放？是否有迟发包绕？ | 保持目标形态而非只跨过出口；出口直段留足长度 |
| 5 | 分别验证恒径 45°、90°柔弯与连续 90°急弯，再验证变径弯管 | 弯曲与变径耦合后是否失效？ | 实际弯角正确，弯中/出口形态，直接滚动，无步态转换 |
| 6 | J4–J9、J8–J13、J12–J17、非零相位与已有不对称搭管姿态 | 接管是否依赖默认位置或相位？ | 几何可支撑时接管；不可接管状态明确记录，不能宣称任意摆放 |

默认角频率 0.6 rad/s 时，3 个周期约 31.4 s。试验时长、直段长度应按实际运行相位和推进距离配置，不能碰到末端后仍把形态变化归因于控制器。逐步推进，已知失败先重现，再比较旧原型、仅修正幅值、仅修改窗口、两者结合；只在能区分原因的场景做消融，不机械地跑全排列。

### 优先级四：分开验证观测与控制，再移植实机

仿真分两条路径：一条用真实接触支持定位控制/几何问题，并明确标为理想观测；另一条只使用实机可读的关节角、原始负载/电流及已发目标，加入与串口采样相符的延迟后验证窗口估计。真实接触只用于第二条的误差评价，不能回灌控制。延迟和噪声未实测时标为假设，不能写成硬件参数。

低置信度时保留当前窗口、暂停相位或请求人工指定支持；这只是可调试的退路，不等于解决失能区域的自动接触识别。只有新方法在保持开放形态的仿真中成立后，才更新 `Rolling_Arc_Real.py`；继续保持一个 Python 文件、集中参数与公式、Ctrl 调试，无 F 键，真实效果由用户实物实验验证。

### 每次实验完成后的固定复盘

报告前查看完整运动、越障后的持续阶段和最差状态：最大包绕角/最小开口、最弱支持、最大力矩和最差窗口交接帧。保留三维侧视与沿局部管轴的端视，叠加实际骨架、目标、使能段和支持观测。自动指标用于筛选，人仍需检查指标是否测到了研究目标；本节为后续实现要求，当前旧脚本尚未自动完成这些审查。

每轮报告必须给出“已验证事实 / 发现的问题与证据 / 原因判断及待验证项 / 下一项最小验证 / 是否满足研究目标”。先评价形态与支撑，再比较同口径速度、每米机械正功、使能关节数及饱和时间；没有电气测量不谈电能效率。未发现新问题时说明审查范围和仍未覆盖的边界，不虚构问题或声称排除了所有问题。这一流程已写入仓库 `AGENTS.md`，后续实验交付持续执行。
