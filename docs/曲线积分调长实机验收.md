# 曲线积分调长：真实机器人试机

当前 `codes/Rolling_Arc_Real.py` 已内嵌仿真验证过的曲线目标生成器，默认 `DRY_RUN=False`，直接通过飞特串口给真实舵机下发指令。只需这一份Python文件，不启动MuJoCo，也不需要实验目录或额外命令行参数。

在原来的Python环境和仓库目录中运行：

```powershell
python .\codes\Rolling_Arc_Real.py
```

仍按顶部 `PORT=None` 自动寻找CH340；需要指定时直接改 `PORT='COM9'`。18关节ID、软件零位、串口波特率和已有调参值保留，本轮不重新标定硬件。`LINK_LENGTHS_M`沿用现有64.5 mm配置，这不是对新连接件实际轴距的确认。

## 操作

1. Ctrl+U形成配置的初始圆弧，等待形成、静置及原两端归零/释放过程结束。
2. Ctrl+4选择主动调长。控制台会显示 `目标生成=拼接曲线积分`。
3. Ctrl+J执行一段**头侧增长、尾侧缩短**；Ctrl+H相反。一次按键仍是一段相对调长任务，到位保持，再按才开始下一段。方向按J1为头定义，与搭管后画面左右无关。
4. Ctrl+G暂停/继续当前任务；Ctrl+L沿当前任务方向强制推进一小帧，发完目标后保持。它没有变成另一个自动流程。
5. Ctrl+Y返回**当前这一段任务的起点**，不代表跨过两个端点后自动回到整次测试的中间。Ctrl+X全部失能，Ctrl+Q退出。

`FEED_DISTANCE_M`默认每段64.5 mm；Ctrl+-/=减半/加倍。调速度仍改 `FEED_RATE_JOINTS_S`，形状幅值仍改 `FEED_AMPLITUDE_DEG`；原 `FEED_OPTIONS_OVERRIDE` 和方向观察器参数入口保留。

建议本次先在中间姿态各做一段J/H，核对方向和实际使能，再逐段向两侧扩大行程并反向返回。观察实际圆弧是否仍开放、长度变化方向是否一致、反向是否接上、旧关节是否退出以及有无反复启停。记录卡住时控制台的阶段和原因即可，不需要另开仿真程序。

## 代码变化与记录

- 只替换目标生成：头尾延伸、肩部与承载弧的曲率子段先拼接，再积分得到目标角；原肩部偏置与中部重分配仍保留。
- J/H状态机、角反馈、长度代理、参考方向、预置使能和退出/缓冲逻辑继承原控制器，没有新增热键或自动往返任务。
- 实机生成器位于文件的 `BEGIN CURVE_FEEDING_CORE` 标记内；顶部FEED参数依旧是日常调参位置。原控制器基类保留供离线对照，实际调长实例使用曲线类。模式5/6内部复用同一调长生成器；本轮的验收重点是模式4。
- 日志自动保存在该文件旁 `codes/logs/rolling_arc_时间.jsonl`。`feeding.trajectory_backend`应为 `stitched_curve_integral`，`feeding.curve_reference`保存实际曲率子段；角反馈、目标、使能和阶段照常记录。
- 长度观察仍用实测连杆几何；原预览的平滑截面显示逻辑保留，不能把它当成世界位置测量。
