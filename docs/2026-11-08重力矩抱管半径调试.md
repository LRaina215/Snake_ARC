# 重力矩越障前的Helix抱管半径手调

本任务与“左右调长／主动送链时的最佳ARC半径”分开。后者仅有110 mm旧模型、50／60／70°双向送链对照，尚未实现自动选取；不是ARC Rolling速度优化。这里新增的是形成小U前，人工调整Helix中心线半径的入口。

用户实测现象：形成小U时全身相对管道打滑。前部保持不足是明确的问题；半径偏大是待验证原因，摩擦、支撑分布和力矩限幅也可能参与，不能直接宣称收紧一定消除打滑。

## 本轮假设与验证范围

假设：在Ctrl+6对准阶段保持滚动相位不变，用热键小步改变Helix半径，平滑形成更紧／更松的螺旋，可为用户实测提供可重复的调试入口。手调只用于对准、小U及直尾形成阶段；原放松／释放、回卷和恢复阶段仍用原半径，保留越障所需滑移。

固定：18关节、既有64.5 mm模型、110 mm主管、原驱动参数；控制20 ms、全身角反馈200 ms。只改变人工请求的半径偏移，不改变使能、螺距、左右送链逻辑或基础ARC公式。控制不读取MuJoCo接触或世界坐标。

验证安排：接口检查覆盖真实／手调键位、连续按键累计、暂停和提前确认、小U形成保留手调半径、后续原放松及回卷参数不变；另从已有成功Helix的实际qpos/qvel做一次短MuJoCo检查，执行收紧、放松、保持和开始小U。保留实际状态、目标、使能和力矩。该检查验证调试功能，不替代完整T管越障，更不能代替用户实机防滑验收。

验收：请求半径分步改变；目标连续、相位在调半径时冻结、使能不抖动；形成小U前半段沿用手调值，后段恢复原释放前半径，释放／回卷及恢复半径不变；0偏移时保持原行为。实际完整过程的支撑、干涉、限位、饱和与漂移另行记录，出现问题据实报告。

## 操作约定

- Ctrl+6进入完整Helix的`align`对准阶段，Ctrl+O每次收紧1 mm，Ctrl+P每次放松1 mm；调节自动平滑执行并保持，不需要另外按G。
- 调节时暂停滚动，相位不变；可多次按键累计。G／空格仍可暂停，J可单步继续。
- 调节完成回到`align`保持。L确认当前姿态，再J/G形成小U；若尚在调节时按L，采用已经执行到的半径，取消剩余调节，仍由下一次J/G解旋。
- 当前Helix半径、请求半径、解旋后段半径及释放／回卷半径显示在K状态与日志中。这些是曲线中心线参数，不是估计的管道半径或接触力。
- 调节值在当前Ctrl+6流程的对准及形成小U阶段保留；原解旋末段恢复95.54 mm、释放／回卷98 mm、恢复94 mm（均为默认值，可在顶部改）。不会修改这些原参数，也不修改模式4调长ARC幅值。新建流程恢复初始设定。
- 单步大小和调节速度在实机文件顶部修改，仿真手调共用同一键位和控制器。

## 验证结果与主动复盘

6项专项接口检查和28项既有相关检查均通过。检查了真实／手调O/P映射、连续按键累计、固定相位与使能、目标斜率、暂停恢复、不重建覆盖设置、提前L采用当前值，以及原放松／释放／回卷／恢复半径不变。没有连接真实串口。

两条12.2 s短仿真从同一已保存的T管Helix实际qpos/qvel恢复。基线保持94 mm，调节例O、O、P累计到93 mm；均在3 s由模拟操作者L确认、G开始解旋，运行到`right_u_hold`并继续保持约1.35 s。这里的世界位姿和接触仅用于评价，不传入控制器。首次基线运行的记录器出现重名字段错误，修复后重新保存，未将未保存运行当作验收证据。

| 指标 | 原94 mm | 手调93 mm |
| --- | ---: | ---: |
| 热键／参数交接检查 | 通过 | 通过 |
| 全程使能变化 | 无 | 无 |
| 非相邻自碰撞／落地 | 无／无 | 无／无 |
| 全身最大实际关节角 | 75.27° | 76.10° |
| 全身最大跟踪误差 | 32.53° | 36.45° |
| J1–J8最大跟踪误差 | 28.02° | 7.08° |
| 至少一关节限矩饱和的50 ms保存帧 | 92/245 | 94/245 |
| 前部接触力低于记录门槛的保存帧 | 14 | 0 |
| 实际达到可释放右U姿态的保存帧 | 0 | 0 |

不能将阶段名`right_u_hold`当作真实U搭稳的证据。按原实际形态判据复核，每50 ms保存的姿态中，两例均未满足“尾部在主管右侧且搭在管上”的释放姿态；调节例尾端最终z≈1.091 m，低于主管轴1.2 m。完整U形成／解旋验收**未通过**，不宣称防滑或T管跨越已经解决。本轮只验证并交付人工调节入口。

基线还有1个保存帧全主管接触力低于记录门槛，几何回放仍有微小负接触距离，不能把这一帧称为整蛇脱管。前部14帧中部分确实未检出前部几何接触，但仍有其他部位接触主管。调节例在此短例的前部接触和跟踪较好，但全身仍有较大误差、饱和，且同样未形成合格U；不能据此推广“收得越紧越好”，也不能证明半径是用户实机打滑的唯一原因。

原因判断：半径会影响前部保持，当前单例提供有限支持；实际U形态还受入场方位、原解旋长度和人工释放时机影响，现有记录不足以归因给其中某一项。未在本轮修改原曲线段长度、放松及回卷方法去追求单例通过。下一项最小验证是用户用O/P实测前部保持，结合实际U姿态选择L时机，保留视频与角反馈日志；本轮没有新增自动支撑门槛。
