# MuJoCo手动调试与实机统一操作

两个入口均直接运行，无需启动参数。在已有`mujoco`环境中选择一个入口：

```powershell
python codes/Rolling_Arc_Debug_Mujoco.py
python codes/Rolling_Arc_Real.py
```

第一条打开MuJoCo手动测试窗口，不打开串口；第二条自动查找CH340控制真实机器人。两端使用同一组全局Ctrl热键，操作时运行其中一个入口。也可在使用该Conda解释器的IDE中运行文件。

## 实际共用的部分

手调版直接导入实机文件中的`RollingArcController`、`global_key_listener`、`process_control_commands`和`poll_control_feedback`。圆弧公式、限速形成、状态切换、单步累加、固定窗口截面顺应、失能与反馈有效性检查都使用同一实现。

| 操作 | 两端相同的结果 |
| --- | --- |
| Ctrl+U | 读取当前位置、预置目标、固定6关节使能、形成圆弧、静置后保持 |
| Ctrl+J / H | 正/反单步；按住不重复累计 |
| Ctrl+G | 连续/暂停相位 |
| Ctrl+E | 固定截面顺应开/关，保留相位与窗口，关闭后限速回基础 |
| Ctrl+空格 / N | 暂停相位但继续顺应 / 冻结最近目标 |
| Ctrl+T、Ctrl+方向键、Ctrl+-/= | 反向、调幅值/频率、调单步步长 |
| Ctrl+K / X / Q | 读取反馈 / 全部失能 / 退出清理 |

完整键位、参数和状态语义见[实机调试说明](实机调试代码说明.md)。基础步态与顺应切换仍保持J8–J13，其余关节失能；手调版没有引入自动滑窗。

## 参数与三维窗口

仿真文件顶部修改`SCENE`、`START_X_M`和日志配置。可选直管`straight`、柔弯`bend90`、连续急弯`elbow90`、变径柔弯`taper_true90`以及110→210 mm急弯`elbow90_taper110_210`。柔弯常用起点−0.35 m，急弯常用−0.25 m。

两端共用的幅值、角频率、固定关节、形成速度、K、yielding、滤波和反馈间隔都在`Rolling_Arc_Real.py`顶部修改，仿真不再维护第二套值。模型PD、力矩上限和被动阻尼来自`configs/step1.json`；实机寄存器原始限扭值不是该模型N·m参数。

查看器使用MuJoCo渲染API，不加载原生viewer的键盘菜单；普通字母和普通空格没有步态功能。鼠标左键旋转、右键平移、滚轮缩放，Shift改变旋转/平移方向。窗口显示步态、模式、窗口、相位和仿真时间，蓝色为使能，紫色为失能。

启动时是静态初始姿态预览，没有推进物理时间或输出支持力。Ctrl+U接管开始动力学，主动按Ctrl+X释放也会结束初始预览；之后暂停相位、冻结目标或失能都不会冻结物理。静态预览不是承重证据，仿真还会默认搭好初始圆弧，真实机器人则读取用户实际搭管的姿态。

仿真关节接口读取当前`qpos`，位置目标不回显成测量；每个物理步按PD和显式掩码施加力矩，失能关节主动力矩严格为零。顺应输入仍为全20关节角，不读取接触力或管径。模型无原始电流/负载寄存器，相关日志字段为`null`。

两端控制周期20 ms、基础读角间隔1 s、顺应全角间隔0.2 s。仿真按仿真时间调度，实机按实际运行时间调度；仿真角连续且读取无串口耗时，真实角有编码器量化和总线延迟。操作和控制实现相同不代表物理响应完全相同。

日志默认在文件旁的`logs/`，仿真前缀`mujoco_debug_`，实机前缀`rolling_arc_`，每次创建新文件。仿真额外保存实际全身qpos/qvel、执行器力矩、物理是否开始及仿真/墙钟时间，可检查实际运动。关闭窗口或Ctrl+Q会执行失能清理。

## 研究实验入口与检查范围

原基础、固定截面、滑动窗口入口及`validation/*_experiment.py`保留作为研究实验工具，不用它们的旧单字母查看器作为统一手调入口。方法实验未被此操作界面修改替代。

本次只做19项针对性检查：17项既有实机算法/协议/启动检查，2项新检查覆盖真实模型读角与初始预览，以及一条完整Ctrl操作流程。后者用虚拟按键驱动真实MuJoCo动力学，共4.92 s、254个保存状态，包含形成、正反单步、顺应开关、连续/暂停、冻结目标、反向、释放和退出；审查全部保存状态，掩码始终0或6，失能力矩为零，未出现形态阻塞。三维窗口也已用保存实际状态完成隐藏窗口渲染与关闭检查。

检查通过，没有连接真实机器人或注入真实操作系统按键，没有重跑跨管实验矩阵。这只确认手调流程和后端连接，不是新场景通过证据；Windows实际按键与实机效果仍由用户操作验证。[检查记录](../validation/reports/manual_debug/README.md)
