# 实际截面顺应与滑动窗口：本轮冻结计划

用户授权：先实现固定6关节窗口的选取、相邻迁移和交接；只有证据表明固定宽度不能兼顾承重与开放形态，才自行开发扩缩。仅仿真与本地commit，实机文件不修改。此前遗留修改不纳入本轮。

## 控制与评价边界

- 截面顺应复用Python实际关节角→正运动学→局部平面→连续线圆弧→Yamada积分。截面模块不读取管道半径、中心线或接触。
- 窗口定位先使用MuJoCo接触的向上承重分量。这是仿真中的理想观测原型，不声称实机失能关节能够取得同等反馈。
- 全局奇偶关节相位保持一致。平滑交接期间共用一个名义180°弧度预算，按使能权重和奇偶分配曲率；窗口外驱动力矩严格为零，机械阻尼仍为1.5。
- 候选须覆盖承重区域且实际形状可用；窗口保持优先，边界载荷持续偏移才迁移。交接要检查新窗口覆盖、跟踪误差和承重，不以计时到点单独判定成功。失败保留记录并退回。
- 保留前轮冻结的实际管轴包绕150–218°、目标截面转角≤190°、端距/主动骨架长度≥0.4、限矩2.355 N·m、无地面支撑、连续失去支撑<0.5 s。
- 急弯横跨两段轴时，单截面管轴包绕不可观测，仍记录为不可观测。新增独立身体开放形态评价：实际角重建截面总转角150–218°、端距比≥0.4、平面拟合RMS≤15 mm；这些条件不能替代“管轴包绕已确认”，分别报告两个结论。窗口交接取整个使能并集，不能只审查重叠区。
- 进度用全身固定骨架点的平均位置评价，窗口移动不会改变评价点集合。全身离开障碍后继续3个滚动周期。
- 不追加反馈延迟、低阻尼、随机扰动或无目的统计重复。每轮先审查全部保存时间点、最差状态及完整侧/端视视频，再决定下一轮。

## 有条件扩缩与修复

先判断失效原因是交接错误、实际窗口位置错误，还是固定弧长不足。只有实际轨迹显示固定宽度的承重与开放条件无法共同满足，才启用长度变化。增加关节时重新分配一个半圆的总曲率，而非保持原60°幅值。形状与承重决定候选长度，管径真值只参与评价。扩缩版本增加1次已知失败场景修复和1次必要回归；其他代码问题也只补最小失败复现与相关回归，并在运行前更新本文件说明理由/预计次数。

每轮报告：已验证事实、失败证据、原因与置信程度、未覆盖范围、下一项最小验证和是否达到该轮目标。保留全部成功/失败的actual qpos/qvel、发送目标、权重/掩码、支撑反馈、选择原因和交接事件。机械正功不称为电能；不能以运动通过替代开放形态验收。

## S1首例后的明确修复（增加1次）

`s1_head`实际完成两次迁移且无失去支撑；但返回交接时发送目标峰值196.56°，并集的管轴包绕最高242.10°，原冻结门槛判失败。完整图中保持开放，没有出口累计收紧；仍保留失败，不能将视觉开放直接改判通过。并集包含进入端的直连杆，指标会在切换统计范围时跳变，这同时提示需要在使能进入端前主动增加开口余量。

修复加入旧窗口内的准备阶段：2 s平滑将名义曲率预算从180°降至150°；只有拟加入的整个并集的实际/发送截面转角均≤165°且开口≥0.4才开始使能交接。交接完成后2 s恢复180°。这保持相同滚动公式和原验收门槛；准备超时保留拒绝事件，不偷偷扩窗。首例修复`s1_head_repair`增加1次，反方向`s1_tail`仍是原计划的第2次且承担必要回归。迁移等待状态可能延长，最长改为80 s，最后交接完成后3周期即停；返回申请为max(24 s,首次完成+6 s)，不向尚未完成的交接重叠发请求。初始11次+该1次修复=12次当前预算。

## S1第二次复盘：按授权启用短暂扩缩（再增加1次）

`s1_head_repair`发送目标最大187.49°，实际身体截面153.15–190.20°，开口≥0.549且全程承重；但7关节并集管轴包绕仍达227.14°，原冻结上限仍判失败，未改判通过。这里存在指标范围变化，但同时启用7关节确实不满足原有完整验收。

设计`6→5→6`交接：准备后先在旧6关节内部把曲率分配给新旧重叠的5关节，退出关节逐步卸载；跟踪和支撑覆盖合格才失能退出关节。稳定5关节段保持150°名义预算，再准备并接入新关节，最终6关节段恢复180°。任一时刻使能并集最多6关节，5关节段每个奇偶族独立分配总曲率，150°预算避免两个同类关节各需90°。这不是按管径增加关节，而是已知交接失败触发的临时收缩/恢复。若支撑不足或目标/实际并集无法打开则拒绝或回退。

新增`s1_head_contract`1次已知失败修复；原定`s1_tail`承担反方向必要回归，总预算暂为13次。两次旧失败仍存档并渲染全程。大管径场景若另有明确弧长不足，再根据该病例证据安排最小扩窗修复和回归。
