# Ctrl+4/5/7公共调长执行器

本轮目标：Ctrl+4只提出相对调长量，Ctrl+5提出准备位置，Ctrl+7提出两侧等长目标；三者统一通过同一个工厂、参数对象、角反馈观察器和advance执行，切换层不再自行推进关节或处理调长交接。局部卷绕、逆向解缠仍是步态切换本身。

验证前的假设：公共执行器可以承接已有半圆，不重建默认60度构型；共享参数修改应同时进入三个热键。先做软件检查与已有姿态核对，再跑1次18关节、110 mm直管、120度起态、1倍动作速度的Ctrl+7完整回归，检查开放形态、归中、扭矩失能及J/H/G返回；有失败才针对修复，不展开场景矩阵。仿真角反馈为控制输入，接触/世界坐标只评价。另对Ctrl+5自动准备的实际入口做必要回归。

此轮改变调长执行与参数传递，不能沿用旧版本动力学通过结论；新硬件25/72/91 mm尺寸仍需用户实机验收。旧的3倍归中形态问题保留原证据，不作本轮成功证据。

## 统一后的调用关系

`RollingArcController.make_feeding_settings()` → `create_feeding_controller()` → `CurveContinuousFeeding` → 同一个继承的`ContinuousFeeding.advance()`。

| 调用方 | 只负责提出的目标 | 公共执行器负责 |
| --- | --- | --- |
| Ctrl+4 | J/H给相对材料调长量，L保留强制小步操作 | 角反馈观察、曲线积分、目标限速、接管展直、使能交接、退出和完成判断 |
| Ctrl+5/6准备 | request_position指定当前承载弧应移到的材料位置 | 同上；删掉原切换层额外的pace/forced_step循环 |
| Ctrl+7归中 | request_center指定长度差为0，传入已形成的连续圆弧 | 同上；删掉原head+=比例误差的独立归中控制 |

形状是公共执行器的输入：Ctrl+4沿用当前曲率分配，Ctrl+7传入已经形成的直线—半圆—直线曲线，平移时保留其半径、长度及相位。没有再从离散关节角重新拼一条半圆。卷绕／逆向解缠仍属于步态切换流程，本次没有把它们当成左右调长重写。

公共配置为FEED_RATE_JOINTS_S、FEED_OPTIONS_OVERRIDE、FEED_DIRECTION_OVERRIDE。5/6准备额外乘HELIX_TRANSITION_SPEED_SCALE，7归中额外乘HELIX_ARC_SPEED_SCALE。旧的7专用center_rate_m_s / center_tolerance_m已删除，防止配置分叉。手动模式的任务距离和是否自动返回仍由4提出，5/7的绝对目标不自动反向。

唯一维护源移到`snake_control/feeding_curve.py`与`feeding_controller.py`；实验目录只兼容导入。单文件实机版本由`python tools/build_real_controller.py`统一生成，仿真热键入口直接继承该实机控制器。用户仍只需运行原来的一个Python文件；顶部硬件配置与当前4倍调参值未改动。

## 实际执行与复盘

只执行3次动力学：7首轮失败、同条件修复复跑、5代表例；没有展开无关测试。原始目标、实际qpos、使能、反馈、按键与各次源码保留在本机`artifacts/shared_feeding_20261108/`，摘要见[results.json](results.json)。模型实测主管半径55 mm、水平直管、18关节、旧64.5 mm骨架；kp=127、kd=1、力矩上限2.355 Nm、失能自由度仍有模型被动阻尼1.5。控制只接收角度与时间；外部几何、接触用于评价和脚本替代操作者确认，未传入控制器。

| 运行 | 已验证事实 | 问题、原因判断与结论 |
| --- | --- | --- |
| seven_beta120 | 流程能结束，失能执行器输出为0，无保存帧触地／自碰撞 | **失败**：最终平面RMS最大34.88 mm、左右长度差72.87 mm，分别超过25/65 mm验收线。关节角投影重新拼成的参考损失连续几何，原因判断较高置信；不能用流程结束代替半圆通过 |
| seven_beta120_curve | 同条件保留原连续曲线后通过；半圆形成后至续滚的全部采样形态通过。续滚包绕176.92–181.78°，最大长度差35.78 mm、平面RMS11.71 mm，J/H相位分别±0.1 rad；G续滚6 s实际推进123.48 mm | 98.35 s走完全程；无保存帧触地／自碰撞、失能执行器输出0。36帧力矩饱和、1帧近零支撑，最大关节78.60°、最大跟踪误差1.73°；没有据此宣称无饱和或全时支撑 |
| five_basic | 从J7–J12起态完成公共自动调长、前部搭稳确认、原回卷送尾、完整Helix保持；全程173.92 s。最终至少1.978圈，最大离轴半径106.82 mm；送尾期间前端推进182.10 mm且始终有主管接触 | 保存帧无触地／自碰撞，失能执行器输出0；84帧饱和、最大关节74.70°。准备阶段近管覆盖最高236.86°，未封闭包绕，但并非始终精确半圆；本轮不宣称最优半径或速度改善 |

除逐帧数值复核，也检查了覆盖整个流程、包含交接和末端保持／续滚的斜视与端视序列。没有看到整段尾部跳使能上管或前后自碰撞。视频保留在各目录的`arc_helix_4x.mp4`和`helix_arc_4x.mp4`，4倍只表示回放速度，本次物理动作倍率为1。

## 软件检查与适用范围

80项相关软件检查通过，包括共享工厂／advance身份、参数覆盖传入4/5/7、原曲线在多个相位无跳变接入、速度倍率、已保存送链目标回放、热键预算／暂停恢复、基础J/H返回和端部归零。清理独立参数后，又跑8项针对共享执行与调速的检查通过；不把重复检查累加成独立用例数。

工作期间新增的Ctrl+4同向连按修复（569cb4b）已保留，另外4项按键回归通过：不清空接管采样／基线、不重复读取18路串口、反向仍可新建任务。合计84项不同用例通过；没有覆盖或回退这次最新Ctrl+4操作修改。

扩大检查的105项中有7项错误、11项跳过；将相同3个旧测试模块换成修改前HEAD实机源码重跑，同样7项错误、11项跳过。其20关节日志／假总线与当前18关节配置不匹配；本次没有把它们改成18关节伪记录，也没有计为通过。

本轮满足“调长执行与参数不再分叉”的目标，代表性动力学回归通过。尚未验证当前4倍设置、准确的新实机几何及真实串口运动，也未重新做T管矩阵。下一项最小验证：用户重启入口后，先用Ctrl+4短行程检查，再执行Ctrl+5成Helix及Ctrl+7归中；只调公共FEED速度即可核对三处是否同步变化。不能把这两例当作所有姿态、速度均稳定的保证。
