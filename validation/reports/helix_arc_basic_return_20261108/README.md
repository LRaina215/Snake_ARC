# 归中后两端归零与基础圆弧接管

## 本轮假设与验收（运行前）

已有实测日志证明：归零在归中前执行，但最终使能窗改变；完成后的H仍被Ctrl+7的调度器拒绝。因此在最终归中后补一次按最终掩码的归零，再退出过渡调度器，能解决遗漏与按键路由问题。失能之后角度仍受接触、摩擦与运动影响，不能保证永久保持0°。

固定条件：18关节、原64.5 mm模型、110 mm直管、同一120°起态和0.2秒读角；控制只读角、尺寸和时间。世界位置与接触仅做评价。改变项为最终端部归零和向基础调度器交接，保留原解缠、成形和归中曲线。

原计划先用已有日志姿态核对，再跑1次完整热键动力学回归。启动时发现用户的`HELIX_ARC_SPEED_SCALE`已手调为3，按该值运行。发现归中中间形态失败后，补1次原验收速度1的相关回归，仅在实验进程覆盖参数，不改用户文件；共2次，不扩大矩阵。不同倍率结果不能用于孤立证明新修复的效率变化。

验收：归中前/后各归零一次；最后撤掉非承载关节扭矩，承载弧不跳变；真正回到基础圆弧；J/H正反相位步长相同并可往返，G按基础omega连续/暂停；开放半圆和归中持续通过原评价口径。保存全程反馈、目标、掩码与命令，并审查形态、支撑、限位、饱和和漂移。

## 修改

- 保留归中前的归零；`center_settle`结束后按最终掩码执行`arc_final_end_reset`。记录两次时机、各自承载/失能关节及结束前最大角；完成/超时分开报告。
- 完成后交回原基础圆弧调度器，保持材料区间、半径、相位、使能和最近目标。J/H按`PHASE_STEP_RAD`正/反，G按`OMEGA_RAD_S`，不再用模式7的一秒动作预算。后续角度裁剪沿用过渡曲线的88°界限。
- 基础单步相位完成后，把最后目标发完才保持，避免微小限速欠量触发下一次反向操作的额外形成/静置。
- 后续实测证明上述处理仍未清除运动命令自动重建分支。已进一步移除自动重建／静置和目标到位等待，将相位完成与目标限速分开，见[后续修复](../basic_hotkey_response_20261108/README.md)。本报告的动力学证据属于当时版本，不冒充后续新实机通过。
- 暂停或单步预算结束时，两端临时扭矩仍立即撤去；接续从最新实测角开始，归零最长累计执行时间仍2秒。受阻导致超时不会被写成已归零成功。
