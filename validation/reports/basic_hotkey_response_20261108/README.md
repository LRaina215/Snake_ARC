# 基础圆弧J/H间歇无响应

## 证据与原因

实测日志`codes/logs/rolling_arc_20261108_165800_988530.jsonl`显示：t=355.89秒正在正常反向单步，静置余量0；t=356.00秒再次H被接受后，静置余量变为2秒。约356–360.4秒仍接收H、累计待执行相位，但相位基本固定在−5.82416 rad。不是该段命令未收到，也不是实测舵机角未通过某个门槛。

根因是运动命令入口比较目标曲线与限速后最近发送角；任意>1e-6°的差异都会重新置`forming=True`和`SETTLE_S=2`。滚动中的正常目标滞后也触发该分支。上次新增的目标误差<1e-8才结束单步又混淆了相位完成和目标到位，现一并去掉。

另一个键盘隐患由本机pynput源码和回调复现确认：KeyCode按字符比较；先松Ctrl时，按下的控制字符和松开的普通字母可能不同，旧held集合未移除原键，下一次同键被当作仍按住而忽略。此隐患不能仅从实测命令日志证明某次遗漏由它造成，故与上面的已记录静置问题分开判断。

## 修复与核对

本轮只改基础运动调度和按键身份，不改变圆弧目标公式或使能区域。假设：正常目标差不再触发建形、静置；单步按相位预算结束，残余目标限速收敛时下一键仍可推进；人工暂停立即冻结；按物理键码配对释放可消除字符变化造成的卡键。

- 去掉运动键触发的自动建形／静置；初始Ctrl+U与显式调参的构型建立各自处理。
- 去掉单步结束的严格目标误差等待。保持相位时目标继续平滑到位，J/H/G可接续，不用等到位；空格/G暂停/N显式冻结。
- 统一按物理VK码记录按下/松开，不按字符对象配对。按住字母的系统自动重复仍只算一次人工单步。
- 使用既有`PHASE_STEP_RAD`与Ctrl+-/=步长接口；`OMEGA_RAD_S`为速度。未擅自改用户参数。

选定实测状态、目标和已接收命令保存在`validation/fixtures/basic_key_pause_20261108.json`。修复前先运行三个回归案例，复现实测状态被重新建形、低目标速率下单步不能按相位结束、字符变化导致第二次同键丢失；实机与MuJoCo类的子案例均失败。修复后增加现有步长配置/热键核对，相关29项软件检查通过。

测试只用内存串口和伪键盘回调，不接设备或安装新依赖。使用本机已有pynput的Key/KeyCode验证比较行为。覆盖连续同向、反向、低目标速率、下一帧相位推进、人工暂停、Ctrl先松后重新按，以及7完成后的双向接管和现有基础控制。

本轮不新增动力学实验，不将软件调度通过写成实机通过或稳定性提升。上轮1倍/3倍动力学结论保持其原条件与限制。下一项最小验证是用户重启旧进程后在已形成的基础ARC中连续按J/H，观察是否仍出现非人为的形成／静置；K显示当前步长和omega。只做本地commit。
