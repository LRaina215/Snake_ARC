# “完成”仍保留非螺旋前部：核对与修复

## 已确认的缺陷

实机记录 `codes/logs/rolling_arc_20261107_163748_814681.jsonl` 第二次切换：

- t=2147.86 s进入 `front_finish`，2151.87 s通过L进入 `first_shift`。此时前部尚是拼接过渡形态。
- 程序锁定这组前部目标，t=2335.27 s报 `complete` 时仍原样保留。前部与当时配置Helix参考的最大目标差约48.95°；允许全身重新拟合最佳相位后，整体目标最大差仍约39.34°，RMS约13.07°。
- 数值证明它不是代码设定的那条统一Helix，不能称为切换完成。用户确认实物搭稳，并不代表软件已经生成同一条全身螺旋；不能将该责任转给操作者。
- 原 `select_helix` 在已有步态开始后只暂停，重复5没有归形用途。原 `complete` 也拒绝J/G继续运动，所以此前没有合适的独立归形入口。

前部起卷函数本身使用非零螺距的螺旋基元，与ARC拼接；整个过渡形态本来就不是单一Helix。缺陷在于提前确认接尾后，混合形态被永久锁住，最后只检查尾段。设计并不要求形成朝内收紧的平面圈。

仅凭无世界坐标的关节记录，不能完整确定现场主管“向前”的空间方向；实际螺旋轴线是否与主管一致仍需实物／视频核对。此次结论针对目标曲线的不一致。

## 修复与操作

1. 送尾结束后先进入 `helix_normalize`，逐渐统一全身目标的半径、螺距、绕向和相位；全身目标到位、角反馈跟随后才报完成。模式6则进入对准。
2. 全身使能时再按Ctrl+5可以选择归形，当前目标保持；J单步或G连续执行。当前处于全身使能的T管状态时，5可以选择退出T管流程并归形。此操作不替代失能尾段的逐段上管。
3. 启动后已有可识别全身螺旋时，Ctrl+5读全角，按实测角预置后使能并保持，下一次J/G才归形。复用原全身Helix拟合范围，不依赖接触反馈。
4. 归形目标采用当前配置的中心线半径94 mm、螺距130 mm、统一绕向和最接近当前反馈的整体相位。每控制步目标变化仍限制为18°/s；不是瞬间拉到目标。

它是显式全身Helix归形，不改局部截面顺应算法；也不代表已实现用户提出的“ARC持续送链、前部持续缠绕”方法。

固定已有实测关节、目标、使能和当前机械模型；只改变最后完成条件与恢复入口。输入截取为[独立实测样本](../../fixtures/incomplete_helix_20261107.json)。先确认原样本的前部参考差大于40°，再验证同一输入归形后全关节目标符合独立计算的常曲率／常扭率螺旋积分。

没有新增实机或完整动力学实验。未验证空间轴线、接触承载、实际滑移和掉落；不能以角反馈到位证明已稳定贴管。旧送尾的实机失败及三个未通过候选仍见[失败记录](../progressive_tail_20261107/README.md)，没有据此次目标修复撤销这些失败。
