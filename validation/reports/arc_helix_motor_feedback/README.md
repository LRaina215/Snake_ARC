# ARC→Helix 三种起态验证

## 头部到达支管远侧后的试靠

复用 x = −320 mm 的竖直支管。以实际头部已有连续四节越过远侧判据、尾段刚确认到 J16 的状态为共同起点。对照和试靠都先冻结尾段进给 3 s，再恢复同一个角度反馈控制器。试靠组用固定支管位置和仿真骨架拟合 J1–J5 的预置角，并把已承重的 J4 拟合改变量限制在 4°。接触力只用于评价。

| 条件 | L0 获得向前轴向反力 | 前部最大回滑 | 从共同起点到成形 | 最多通过的连续头端连杆 |
| --- | --- | ---: | ---: | ---: |
| 同姿态对照 | 无 | 31.6 mm | 41.9 s | 5 节 |
| 前端试靠远侧 | 无 | 49.2 mm | 47.5 s | 5 节 |

两组均完成约 2.2 圈的 Helix 并保持 2 s，未落地。试靠期间两组都只确认接入到 J17，尾端没有从该动作获得可测的上抬收益。第一轮在较早的两节通过姿态试靠时，J4 也曾持续饱和。随后用接触几何复核，分配版的拟合形状虽能从下游侧碰到支管，前部同时会侵入主管约 39 mm，仿真动力学中实际无法到达。固定其余身体、只扫前部螺旋半径和相位的几何筛查同样没找到接触远侧且与主管相容的构型。该筛查用于检查可达性，未作为动力学验证。

本轮确认头部能先到远侧，尚未建立可供尾段借力的支点，也没有验证较早接管尾段或实机。首要问题是给前部留出沿主管外侧升到支管接触高度的几何路径。两轮输出保存在 `artifacts/arc_helix_tee_far_side`，共同起点、力、目标和状态均随记录保存。

```powershell
python .\validation\arc_helix_tee_far_side.py --output artifacts/arc_helix_tee_far_side/distributed_brace
```

## 借 T 型支管辅助尾段卷入

假设已贴住主管的前段能借支管限制回滑，让后段更容易接入，并在切换中使部分头部连杆到达支管远侧。三组复用同一个 20 关节、113 mm 主直管和同一全状态检查点。此前近等长 ARC 已把窗口调到 J3–J8，头端 L0 已贴住主管，J9–J20 失能。加管组的上向竖直支管直径 60 mm、高 600 mm，从主管轴起。红线附近的位置取世界 x = −370 mm，延后接触的位置沿前进方向移 50 mm。各组采用同一个角度反馈控制器和同一反馈时钟。支管反力只用于评价。

| 条件 | 从分叉到成形 | 尾段最远确认 | 通过支管远侧的连续头端连杆 | 前 85 s 力矩饱和帧 |
| --- | ---: | --- | --- | ---: |
| 直管对照 | 85.8 s | J20 | 仅作动力学对照 | 94.2% |
| 红线附近 | 115 s 内未成形 | J18 | 0 节 | 99.8% |
| 支管前移 50 mm | 108.4 s | J20 | 最高 4 节，2 s 保持期间至少 1 节 | 99.7% |

远侧判据为从头端连续计数，连杆两端的 x 均超过支管远缘 20 mm。这个判据用于区分局部通过和整机通过。三组的续跑均无落地，失能执行器输出为零，50 ms 记录中持续有主管接触。红线组首次接触为 L4，发生在 J9 接入前，轴向反力 −6.4 N。该组短时先到 J15，但后来卡在 J18，末态仅约 0.81 圈。支管前移后首次接触为 L5，尾段接入已经进行到 J11，最后保持约 2.20 圈。

两种支管位置的记录都没有向前的净支管轴向反力。前段最大回滑约 28 mm，直管约 4 mm。延后接触证明切换与部分通过可同时发生，成形比直管多用约 22.6 s，未表现出尾段减负。当前结果支持先让头部有空间绕行，再考虑在支管另一侧建立借力接触。未验证该接触能否助推、整机通过或实机表现。

```powershell
python .\validation\arc_helix_tee_brace.py --output artifacts/arc_helix_tee_brace/marked_position
python .\validation\arc_helix_tee_brace.py --branch-x -0.320 --tee-only --output artifacts/arc_helix_tee_brace/delayed_contact
```

## 先调短前侧，再由前端引入 Helix

本轮使用同一个 20 关节模型、113 mm 直管、管面摩擦和反馈周期。起态为近等长 J8–J13 和前侧中等偏短 J5–J10，均取头侧为前进端。实验模式逐节调整使能窗，每次交接后读取角反馈、重建前侧余长。进入短端范围后，前段单独向前卷入，原 ARC 继续承托，后段保持失能。短前段先形成稍紧的螺旋，逐节接入后段时再过渡到统一半径。后侧的下一个关节在上一节跟随后才使能。

控制器只读关节角与时间。后侧开始接入前，要求头端相对拟合截面具有沿目标方向的轴向位移、符合接入方向的连杆切向，以及接近拟合圆柱面的径向位置。真实主管接触只在验证端判定。验收要求头部连杆 L0 先接触主管并相对 ARC 向前至少 20 mm，随后后侧才上管，成形后满足下述 2 s 保持要求。

| 起态 | 调整次数及结果 | 前端贴管并前伸 | 后侧首次使能 | 成形 |
| --- | --- | ---: | ---: | ---: |
| 近等长 | 5 次，J8–J13 → J3–J8 | 46.60 s / 47.5 mm | 46.85 s | 132.40 s |
| 前侧中等偏短 | 2 次，J5–J10 → J3–J8 | 27.50 s / 43.3 mm | 27.65 s | 116.00 s |

时间扣除起始 3 s 静置。两组最后的最小实际包绕均约 2.19 圈，失能执行器输出为零，记录中后侧每次最多新使能一个关节。完整过程中无落地。近等长组调长阶段有两个连续 50 ms 记录帧的主管支撑为零，随后恢复。两组达到仿真力矩上限的记录帧分别约占 62% 和 71%。

早期试验仅按前段角度跟踪判断到位，交接过早。改成可延伸前螺旋后两组能成形，但 L0 仍晚于后侧接入才碰管。最后在前侧多留一个可控关节，并对短前段局部收紧，才在两组中验证到真实的先后顺序。此次证据覆盖这两种直管起态，其他相位和实机表现待验证。各轮的目标、角反馈、掩码及物理状态保存在 `artifacts/arc_helix_prepared_front`，最终运行目录以 `tighter_` 开头。

```powershell
python .\validation\arc_helix_motor_feedback.py --case balanced --prepare-front --output artifacts/arc_helix_prepared_front/balanced
python .\validation\arc_helix_motor_feedback.py --case right_moderate --prepare-front --output artifacts/arc_helix_prepared_front/right_moderate
```

## 近等长分段卷入与中等偏长回归

近等长分支在两侧估计长度差不超过两个平均关节间距、两端均有三节以上材料时使用。当前搭管方向的左侧是尾侧。第一段保留支撑 ARC，只增长左侧螺旋。达到左侧曲线长度且三个新角度样本跟踪通过后，右侧才开始逐节接入，原 ARC 随之缩短。控制决策继续只使用关节角和时间。实机的先卷端用头尾编号定义，世界左右随搭管方向而变。

| 起态 | 起态头／尾长度估计 | 路径 | 成形用时 |
| --- | ---: | --- | ---: |
| 近等长 J8–J13 | 526／461 mm | 左侧先卷，右侧随后接入 | 56.54 s |
| 左侧中等偏短 J11–J16 | 705／254 mm | 短侧起卷，直接移位 | 31.80 s |
| 右侧中等偏短 J5–J10 | 317／639 mm | 短侧起卷，直接移位 | 54.40 s |

近等长对照沿用相同主管、姿态和手调按键时刻（Ctrl+5、Ctrl+J、Ctrl+G）。旧版在 0.82 s 同时使能 J7 和 J14，新版在 0.82 s 开始左侧，34.56 s 才有右侧关节使能。交接前仿真记录有左侧 L20 与主管接触，右侧窗口外仍为零执行器力矩。整段 20 ms 记录的峰值关节角速度由 62.0 降至 39.2°/s，每帧最陡关节角速度的第 95 百分位由 26.8 降至 14.9°/s，成形时间由 31.68 增至 56.54 s。达到仿真力矩上限的帧仍约占 52%。近等长试跑和两个中等偏长试跑均通过下述保持验收。中等偏长的测试保持连续推进，三者用时包含的操作停留不同。

本轮支持近等长分段和上述两个中间起态。极短分支沿用原路径，本轮未重复运行；实机承载与其他初始相位待验证。分段回放及 20 ms 指令日志保存在 `artifacts/arc_helix_staged/verified_manual`。

## 首版同时接入的三种起态记录

以 20 关节的实机配置为目标。三组使用同一个外径 113 mm 的水平直管、起点、摩擦、执行器模型、初始相位和参数，只改变 ARC 的搭管位置。沿主管朝 +x 看，画面右侧是 −y，左侧是 +y。稳定 3 s 后，三组的使能段实测总转角均约为 180°。

控制器每 200 ms 接收全身关节角和时间戳。它重建全身骨架，在已使能 ARC 的拟合截面里，从弧顶向两端寻找骨架第一次穿过圆心高度的位置，沿骨架估算两侧长度。两侧长度决定从哪一端起卷，起卷端相对圆心的深度决定是否先调一节。首次按 Ctrl+J 或 Ctrl+G 时重读角度并重算。卷入沿同一条拼接曲线改变采样区间，前部螺旋段随移位增长，另一端的关节随交接逐个使能。仿真使用位置目标和二值使能，失能关节的执行器输出为零。主管位置、碰撞和支撑只在验收端使用。

验收要求为切换完成后保持至少 2 s，实际骨架包绕至少 1.6 圈，距轴最大径向距离不超过 145 mm，头尾各有主管接触，且全过程无落地。时间从 3 s 静置结束计起。

| 起态 | 初始使能段 | 头／尾悬垂长度（连杆当量） | 执行分支 | 成形用时 | 保持期最小包绕／最大径向距离 |
| --- | --- | --- | --- | ---: | ---: |
| [近等长](balanced/result.json) | J8–J13 | 8.55／7.46 | 直接卷入 | 30.0 s | 2.20 圈／105.2 mm |
| [左侧极短](left_short/result.json) | J14–J19 | 15.48／0.49 | 先移到 J13–J18，再反向采样逐关节接入 | 89.0 s | 2.20 圈／104.5 mm |
| [右侧极短](right_short/result.json) | J2–J7 | 1.66／14.41 | 直接卷入 | 112.6 s | 2.21 圈／103.4 mm |

## 复盘

- 左侧极短时，直接反向采样的试跑虽然接受了全部关节，末态实际只有 0.44 圈。连续向中间移动使能窗的试跑在第四次交接后失去主管支撑并落地。最终只调一次。该起态由关节角重建的短端深度约 73 mm，右侧极短约 138 mm。以 1.5 个平均关节间距（约 97 mm）决定是否给起卷肩部腾出一节，能够区分本轮起态。这个阈值目前只由本轮结果支持。
- 检查了全部 50 ms 记录帧。三组都有主管支撑、失能输出为零，保持期间没有力矩饱和。切换过程中分别有 419／1617／2025 帧至少一个电机达到仿真上限 2.355 N·m，实测角最大约 90.12°，已使能关节的峰值跟踪差分别约 36°／51°／56°。右侧极短成形最慢。两种极端起态在过渡阶段仍有长端悬垂，直到对应关节陆续卷入。
- 三个指定的起态达到直管成形目标。内存串口检查保持 J8–J13 使能，先用近等长反馈进入模式，再用头侧屈曲反馈启动单步。初选为直接卷入，启动时重估后改为先调一节。这个检查只验证入口会按新反馈改变计划。仿真力矩上限与飞特舵机的原始限制寄存器未做等效标定。其他初始相位、管径、边界姿态和实机承载尚未验证。实机首轮可从近等长起态按 Ctrl+5、Ctrl+J，观察最先接管的关节与角度跟踪。

## 复现

在 `mujoco` 环境和仓库根目录运行以下命令。每组的 `result.json` 保存参数、交接事件、角反馈和支撑真值，`trace.npz` 保存对应帧的全身状态、目标、实际执行器力矩和使能掩码。

```powershell
foreach ($case in 'balanced', 'left_short', 'right_short') {
    python .\validation\arc_helix_motor_feedback.py --case $case --output "validation/reports/arc_helix_motor_feedback/$case"
}
```
