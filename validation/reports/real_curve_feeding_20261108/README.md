# 曲线积分调长实机移植

交付 `codes/Rolling_Arc_Real.py`：默认真实飞特串口，`DRY_RUN=False`；保留18关节配置、已有ID/零位、用户串口/速度/幅值设置。用户直接运行该文件进行真实机器人验收，不启动仿真，不附加启动参数。

将已验证的曲线构造与积分内嵌在 `BEGIN CURVE_FEEDING_CORE` 中，`ContinuousFeeding` 默认绑定曲线子类。原控制器保存为 `LegacyContinuousFeeding` 仅作离线比较；advance、request_step、强制推进、接管、长度观察及使能退出方法继承原实现。J/H/G/L/Y/X的映射不变。模式5/6内部调长也复用这个类，没有另改其运动流程。

数学源仍在 `experiments/curve_feeding/curve_profile.py` 与 `backend.py`；`tools/build_real_curve_feeding.py`只在构建时提取声明，运行实机文件不需要这些文件。保留主入口单文件可复制性。其他内嵌核心及未提交的用户调参没有通过全量重建覆盖。模式4状态明确显示目标来自拼接曲线积分，日志新增 `trajectory_backend` 和 `curve_reference`。

## 验证与边界

没有连接硬件，没有新增MuJoCo物理试验。本轮是已有方案移植，用 `validation/test_real_curve_feeding.py` 完成6项必要检查：

1. 真实连接默认值、18路表、Ctrl热键及上层继承关系保持。
2. 1,200组18/20关节、窗口、相位、幅值和位置比较；相对旧目标最大差 `1.08e-15 rad`，与实验曲线源一致。禁用旧模板后，新目标仍能生成。
3. 之前完整行程的12,291个控制帧逐帧核对目标生成，实机嵌入与实验曲线源差0。只复放保存的角度/参数，未写成新实机运动通过。
4. 使用内存飞特串口发送真实协议包，J/H任务、G暂停恢复、L一帧、Y返回和X扭矩关闭读回通过。未把软件舵机跟随目标写成真实机器人跟踪。
5. 单独复制Real.py到临时目录，使用隔离Python导入，禁止导入仓库模块、MuJoCo及串口模块仍能初始化曲线核心。
6. 内嵌构建重复执行不变，模拟手动端口/幅值改动得到保留。

具体计数见 `checks.json`。原先全行程的回中长度偏差、部分过渡开口不足及重复交接仍存在，未在本次移植中顺手改算法，也不宣称实机已通过。现有实机 `LINK_LENGTHS_M`仍为旧64.5 mm配置，本轮没有重标新机械轴距。

用户的下一项最小验收：按原操作先做中间一段J/H，核对方向、使能和接管，再扩大行程并反向；卡点保留控制台与自动日志。见[实机操作说明](../../../docs/曲线积分调长实机验收.md)。
