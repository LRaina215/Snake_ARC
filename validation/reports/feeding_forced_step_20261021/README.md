# Ctrl+L强制沿当前任务方向推进

2026-10-21，用户要求保留J/H逻辑，将无反应的Ctrl+L改为强制推进一步。

假设：旧L只调一次正常闭环，仍受接管、跟踪误差和观测条件阻塞。固定当前模板、J/H任务状态机、8°手调容差、机械尺寸和限速；只增加明确的手动强制分支。验收为每个L命令只增加一次指定方向的分布坐标、即使反馈不跟随/观察不可用也发送目标、发送完保持，且J/H和旧记录清理仍正常。

## 行为

- `FEED_FORCE_STEP_JOINTS=.05`：每次推进0.05个关节间距的弯曲分布坐标，不称为真实材料移动3.225 mm。
- 方向来自当前J/H任务请求；手动返回阶段反向。到位或尚未开始的任务也可用L明确发起一步，不自动连续执行。
- 跳过接管标定、跟踪误差、包绕角/长度观测对位置推进的阻塞；仅此强制分支改变，不修改普通J/H判据。
- 保留已有使能，按新模板/缓冲补足必要关节，进入关节按实测角预置。不在此分支执行自动释放。按原45°/s目标限速、最多20 ms的单次更新平滑发完目标，再由入口保持。实际舵机是否达到目标不作为发送完成条件。
- 保留当前基线与长度目标；尚无基线则不凭空生成。清理旧采样/速度和等待计时，原故障写入`forced_step_requested`事件。G恢复原阶段，J/H重新开始相对任务，X立即失能并丢弃任务。
- 模板坐标边界、当前完整有限角反馈、串口编码检查保留。边界处输出未推进原因；这不是无限制生成关节目标。
- 实机内嵌与研究核心同步，MuJoCo调试直接继承该入口。帮助文本和文档已更新。

## 复盘

已验证L不会再因8°误差或参考采样不足而无目标变化，且不会自行继续整段任务。目标发送成功不等于机器人克服卡滞或实际移动达到请求；软件测试不能证明完整反向调长能力。

没有新实机或动力学实验，开放形态、曲率、支撑、关节限位/力矩饱和、真实失能后行为及漂移没有新增验证。最小下一项是用户在原卡住位置按一次L，核对目标与实测变化，再决定按G继续或再按L。
