# Ctrl+5 自主准备与前后分段上管修复

2026-11-07：本轮10类入口完成仿真验收，实机未验证。旧 `mode_handoff` 的九类通过结论已撤回：漏查了全程前后段干涉，以及首次送尾期间前部继续移动的问题，旧视频不能作为新版本验收证据。

## 本轮假设与验收

Ctrl+5 应完成一个任务：从当前实测 ARC 识别承载特征与两侧余长，自动用模式4的拼接曲线调整材料分配，先形成前部承载螺旋，前部实际搭稳后才逐节接入尾段。Ctrl+6 复用这一入口，再接重力矩流程。不能要求用户先用模式4摆到指定窗口，也不能把模式4的所有缓冲使能都误当成承载 ARC。

固定条件为18关节、间距64.5 mm、起始圆弧幅值60°、Helix中心线半径94 mm／螺距130 mm、主管直径110 mm、上向T支管直径60 mm、摩擦0.5、单关节限矩2.355 N·m。控制周期20 ms、全身角度回读周期200 ms；通过实机独立文件的控制器和仿真调试入口的二值电机总线运行。改变变量为入口模式、初始窗口、模式4送链方向及初相位。

控制器只接收实机可读的角度、使能状态与时间。接触、世界坐标和支管位置只用于试验中的操作者 Ctrl+L 确认与结果评价，不传入控制算法。现场搭稳和重力释放的确认仍由用户观察。

验收检查完整实际运动：

- 自动调长保留开放承载弧，使用最新形状重选窗口，不能通过重置位姿完成准备。
- 首次上管期间后部未接管的关节保持失能；前部实际绕管至少0.9圈、最大离轴半径115 mm以内，并在相隔至少3段的两处建立主管接触且连续0.8 s，才模拟操作者确认。
- 首次送尾期间前部已发角度目标逐帧不变，实际前部仍保持绕管与支撑，尾段逐节接入。
- 每1 ms物理步检查所有非相邻（间隔超过2段）连杆碰撞；每50 ms另存实际全身状态、目标、使能、力矩、反馈及命令。不能以端视投影的重叠直接证明有碰撞或无碰撞。
- 调长及模式4准备阶段另查真实主管轴周围145 mm内骨架点的最小极角覆盖，须小于300°以保留至少60°开口。这是包含近管切线段的离散覆盖角，不是截面半圆本身的总弯曲角，也不拿它代替支撑检查。
- Ctrl+5完整螺旋保持3 s，实际全身包绕不少于1.5圈、离轴半径不超过145 mm且前后有主管支撑。Ctrl+6整身越过支管后持续贴管滚动10 s。失能电机力矩为零，全程落地、限位、饱和及支撑中断单独记录。

先复现已知失败 `feed_h5` 和直接 `buffer6`；修复后相关回归包括基础5、模式4 J/H后5、头短/尾短5、直接6、5后6、不同相位6、模式4 J/H后6。只为诊断失败新增局部恢复实验，不以增加次数代替验收。

## 已发现问题与修正记录

1. 前部起卷时同步滚动，头端扫向尚失能的后段；已移除这一滚动，并限制初始头端材料。前部螺旋所需的整段材料按半径、螺距及关节间距计算，不能再只增加悬垂头端半圈。
2. 长距离自动调长提前撤掉旧接管关节，后段留下弯钩；已复用模式4的曲线送链和相邻接管，并在自动准备时保留输入相位。
3. 重新规划的一帧仍输出旧缓冲使能；现在同时更新目标阶段与使能掩码。
4. `round11/feed_h5` 虽跟到全部尾关节目标，实际前部受载拉开，最大离轴半径224 mm、仅约0.95圈，判为失败。不能只放宽角误差宣布完成。最初怀疑局部相位补偿，但相近相位下仍有成功与失败，不足以把它认作唯一原因。
5. 将前部使能直接从9增到11也不是修复，`round12` 的直管和T管在前部成形时均发生头尾接触，失败记录保留。直接用解析直尾替换实测曲线也拉开前部（round13、14），未保留该替换。
6. T管释放后的原回卷在新入口下卡住。与用户提供的实机版2核对后，补回按序恢复切线圆弧和直尾的步骤，再缩短直线段、补偿前部相位。局部恢复记录 `source_return` 最终约1.99圈、最大离轴半径105 mm且无非相邻接触；它只证明该释放后状态能恢复，不代替完整Ctrl+6回归。
7. 首次送尾的主要时序问题是误把“已确认前缀”改成“当前新关节必须先到位”，让下一交替转轴一直失能，整条尾部被单轴掰动。现恢复相邻转轴前瞻接管：确认已接管边界，同时让紧邻下一轴参与实测曲线；前部目标仍锁定。round17的已知H→5失败与round18其余四类5都通过完整实际形态、支撑与无干涉检查。
8. 重新卷成Helix不等于T管越障。round18直接6虽全程无非相邻接触、完成回卷，却仍停在支管前，判失败。保持原实机直尾恢复流程，在重力矩回卷阶段叠加0.084 rad/s前部滚动；该阶段与首次ARC接尾时的前部锁定明确分开。局部恢复 `return_roll_probe` 无非相邻接触，最后端到804.6 mm；随后round19的五类完整T管路线均通过。
