# 模式4同向连按无动作调查与修复

用户反馈Ctrl+J/H有时无响应。此次用最近的实机日志定位，未连接真实串口、未跑新的MuJoCo物理实验。原假设是“按键已收到但重复任务初始化或读角阻塞主循环”，没有先假定键盘失灵，也没有继续增加运动放行门槛。

## 已确认事实

`codes/logs/rolling_arc_20261108_182119_098682.jsonl`中，2825.516–2851.078秒的406行模式4记录保存为 `actual_mode4_slice.jsonl.gz`。

- 39条J命令进入控制器，日志均为accepted，任务ID升至39；最后只完成一段相对调长。说明这些键并未丢在键盘监听层。
- 每次重复J都会调用`request_step`，清空长度基线、接管稳定采样，重新进入acquire。许多连续按键后采样退回0/1；已在运动时再次按J也会中断计量并重新接管。
- `start_feeding`先完整读18路角，再调用`resume_feeding`重复读18路。快速连按时主循环会被额外串口读占用。日志中同一循环批量处理多个J不等于用户同一毫秒按了多个键，不能由此断言键盘抖动。
- 此外仍出现`no_stable_passive_segment`。它与重复初始化是不同问题；日志不足以把所有等待都归因于本次修复的两处缺陷。

原0.6秒稳定采样与8°跟踪条件服务于接管后的长度计量：接管未到位时的形变不能直接算作已送出的长度。它们不是“替用户承担风险”的许可判断。本次曲线移植未新增这些旧条件，但移植时没有覆盖“运行中反复按同向键”的操作，这是上一轮检查遗漏。

## 修改

1. 同向任务仍在运行时，J/H保留当前任务、基线、采样、目标和掩码，返回`feeding_continues`，不重启任务，也不暗中积累多个任务。
2. 此分支不再主动读串口，读角由原主循环按周期进行。确实需要新段或反向时只完整读一次，不再重复读两遍。
3. 反向、暂停后新段、完成后新段、Y返回中断等入口保留。没有把J/H改成L，也没有改长度/跟踪阈值。
4. 控制台明确确认同向继续；命令日志记录`continued`及模式4真实阶段，不再把模式4的stage总记成None。

主仿真调试继承同一实机控制器，因此同样使用修复后的命令处理；没有另外运行它进行运动验证。

## 必要检查与限制

对照版本固定为`ee22e39`，仅用内存飞特串口。4项针对检查见 `checks.json`：

- 每0.2秒重复J，持续3秒：旧版仍acquire、位置0、重建15次；修复版进入feed_out，分配位置约0.212，无任务重建。这是软件舵机复现，不是实机已经成功移动。
- 同向按键旧版发送36条读寄存器包，修复版0条；反向新段只需18条。采样/基线、目标与使能保持检查通过。
- 反向、暂停/完成后的新段、从返回状态开始新任务及X扭矩关闭均检查。
- 分派记录能区分“已收到并继续”与拒绝，真实feeding阶段不为空。

另核对原曲线实机入口的J/H/G/L/Y/X串口路径、单文件导入及基础ARC按键/监听回归，结果见 `related_checks.json`。没有做哈希检查或追加物理试验。

已修复已复现的任务重置与重复读问题，不能据此保证所有J/H无动作都解决。原参考方向、计量和跟踪等待仍可能出现；本次没有宣称已删除它们。下一项最小验收是重启实机脚本，在模式4连续同向按键，观察任务ID不再反复增长、采样不再因按键清零、随后能反向；保留自动日志即可。
