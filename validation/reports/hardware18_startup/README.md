# 18关节启动配置修复

2026-11-07，软件检查通过；未连接真实串口，未新增完整运动实验。

后续已确认：本次只修复了数量一致性，沿用的旧校准仍不匹配当前装配的直线基准。当前软件零位已改为用户确认直线姿态的新标定，见[新校准与核对](../hardware18_zero_20261107/README.md)。下述“旧校准前18项”保留为此次数量修复的历史记录。

## 原因与修改

用户将 `NUM_JOINTS` 改为18后，原 `SERVO_IDS` 和 `ZERO_RAW` 仍有20项，`validate_setup()` 因数量不一致退出。原默认配置没有与真实18关节硬件统一。

- 现在默认18关节，ID为1–18；保留原校准值，按数量取前18项零位。方向、限位18项、机械尺寸19段。没有猜测新零位。
- 检查仍保留，配置错时会明确指出 `NUM_JOINTS` 与哪张表的数量不符；重复ID单独提示。窗口／步态维数的报错改用实际数量。
- 手调普通场景原先固定加载20关节XML；现在按18关节裁掉模板最后两节和对应执行器，移动尾端点，保留原管道几何和物理参数。已有18关节T管模型直接复用。研究入口原20关节模板未修改。

## 必要验证

1. 重现原错误：18关节配20项零位表被拒绝，错误明确含 `NUM_JOINTS=18`、`ZERO_RAW=20项`。修复默认配置后启动检查通过。
2. 内存串口的12项控制检查通过：18项校准映射、只访问ID1–18、先预置再使能、失能、启动、单步，以及模式3/4/5/6接入和控制帧维数。未打开真实设备。
3. 直管、110→210→110变径直管和T管三个手调场景加载、接管首步、反馈及重置通过：均18执行器、25个qpos元素、18个目标／读角；失能执行器力矩为零。这些是初始化检查，不作为新步态通过证据。

本机记录为 `artifacts/hardware18_unit_checks.log`、`artifacts/hardware18_startup_checks.json`。原18关节运动结果仍见[分段切换报告](../sequential_handoff/README.md)，实机效果由用户验收。

## 用户启动

更新 `codes/Rolling_Arc_Real.py` 后，在原环境和目录直接运行：

```powershell
python Rolling_Arc_Real.py
```

无需额外启动参数或手动删方向表。若硬件使用非连续ID，仍按实际关节顺序配置 `SERVO_IDS` 与相应零位。
