# 接管后标定与J/H手动分段送链

2026-10-21。针对实测调查的修复；不连接硬件、不新增动力学，不将离线通过写成实机通过。

## 本轮范围与验收口径

假设：起态基线先于缓冲区接管展直，使后续几何变化混入本步进度。固定原始角反馈、机械尺寸、形态分配、目标限速和串口协议；只改接管/计量阶段与手动动作生命周期。检查基线是否在展直稳定之后建立、期间位置参数是否保持、J/H是否保留既有弯曲分布且到位保持。开放形态、支撑和真实转移仍需实机验收，不能用这些软件条件替代。

## 修改

1. `prepare → acquire → feed_out → complete`。首次形成后先接管邻近弯折，`acquire`中弯曲分布位置固定，目标按原限速展直，尚无长度基线。
2. 至少3个新角反馈、稳定跨度0.6 s，跟踪误差≤5°，全关节角波动≤3°、长度代理波动≤2 mm后才建立本步零点。新增使能或参考段变化重新收集稳定样本；重复时间戳不积累。10 s仍未稳定时保持并输出原因/数值。参数可自行调整。
3. 默认关闭自动往返。Ctrl+J/H每按一次执行一个正/负向相对任务，到位保持；默认请求64.5 mm，可减半或加倍。再次按键保留位置参数、目标、窗口、观察器和历史支撑，不先恢复最初J8–J13形态。运行中按键替换未完成目标，不排队。
4. 后续动作重新在接管稳定后建立本步基线，不重复6 s初始形成。反向时保留已有失能参考侧，避免两次动作依次占用两端使参考全部消失。
5. Ctrl+G只恢复未完成动作，已完成时保持；Ctrl+Y保留手动返回本步基线。Ctrl+L仍是一个目标更新；按住J/H的自动重复已由原热键监听抑制。
6. 研究核心和实机嵌入核心同步；仿真调试入口复用同一个控制器。现有研究往返通过`automatic_return=True`保留，但此前动力学不能作为本次修改的通过证据。

## 核对结果与复盘

- 实测任务19原始行9384/9386/9390/9394/9399，来自上轮已冻结的`passive_segment_selection_20261021/actual_log.jsonl.gz`。原观察器9.12与17.01 mm跳变期间，新流程仍在接管阶段，基线为空、位置参数为0；研究与实机核心在此回放中目标/掩码/阶段一致。
- 片段后补固定角反馈，仅检查稳定后能标定且进度从0开始；该补段为软件夹具，**不是用户实机后续运动**。输入时间按0.2 s新反馈重采样，不冒充完整按键/真实时间回放。旧记录本身不能证明机器人执行新命令后会经历相同姿态。
- 内存串口完整执行“正向→正向→反向”，每项到位保持，第二项位置继续正向、第三项反向，没有自动返回事件；完成后继续采样及按G都不会启动下一段。内存舵机直接追随目标，不代表真实负载下能达到请求距离。
- 26项针对性检查通过：上述3项，加6项核心、6项选段、11项串口/操作/独立单文件/仿真共享入口检查。检查结果见`checks.json`。全记录回放会覆盖旧报告且不能给出新闭环真值，本轮未运行。
- 开始检查时旧测试要求第6秒附近立即得到基线，因新增接管稳定阶段失败；已改为明确检查先进入`acquire`、后建立基线，并延长相关操作夹具的等待。没有通过降低真实观测质量门槛来迎合旧测试。

原因判断：基线早于接管的执行顺序已确认，本次软件修复移除了该启动计量路径。实机实际转移不足是否主要由此造成仍未证实。运动过程中虚拟切片的形状耦合仍存在，本次不以不停归零或扣除未知“误差”的方式隐藏它；界面长度仍明确标为几何代理。

无新动力学或硬件动作，故没有新的全过程开口/曲率、接触支撑、力矩饱和、失能后的机械阻尼、空间漂移真值。下一项最小验收是用户在同一装置上按一次J、到位后对照材料标记，再按H观察反向能力；不需自动往返或扩大测试矩阵。修复的软件目标已通过，真实调长能力待用户确认。

相关操作与DIY参数见`docs/主动送链实机验收说明.md`。使用现有Conda `mujoco`，没有安装依赖。
