## 本轮结论

已实现按实测身体截面覆盖角选数量，能增也能减；数量目标不再引用初始幅值。110→210→110 mm 直管中实际完成 6→5→6→7→6→5，两个平移交接，返回小管后再滚动完整一圈。大→小段身体半径随之下降，控制未再停留在大管构型。

**尚未达到全过程严格半圆验收。** 自动例初期真实绕管最大235.62°，累计4.84 s超过历史218°门槛；扩径中最小133.00°，也低于历史150°下界。后段缩径完成后的最后一圈为188.21°–197.97°。这些不是通过改门槛消除的误差，不宣称整个Step2、急弯回归或实机运动通过。

## 方法与反馈边界

- 保留参考仓库 `pole_compliance.py` 的实测平滑截面、等长半径/转角变形及曲率积分思想。增加一个离散逆算补偿：按本帧实测曲线经原gain变形后的总转角调整积分结果的整体尺度，弥补曲线转舵机角再重建的转角损失。该目标来自实测曲线，不是π，不是初始幅值，也没有名义圆弧恢复项。默认开启，`SectionOptions.correct_discrete_turn=False` 可单独核对原积分。
- 对实测投影点拟合身体圆，使用极角覆盖 `coverage`；所需数量代理 `N*180/coverage`，多相位均衡后决定单边增减，候选优先接近180°。拟合半径是蛇身半径，**不是管道半径测量**；实际切线总转角与覆盖角分别保留，不能互换。
- 连续内部窗口至少3关节，两端需保留边界。取消以名义π分配能否通过限位来否决五关节候选，实际角与交接仍被检查。没有固定6/8白名单。
- 控制只收全关节角、采样/控制时间、已发相位和当前掩码。管径、根部位置、世界重力、接触力、qvel只用于物理执行或离线评价；没有加入选窗输入。

## 实机推荐始终不执行：已确认的软件原因

只读检查 `codes/logs/rolling_arc_20261013_232455_267867.jsonl`：324条推荐中195条向尾、129条向头，均无`down_head`，均被旧执行层标成`retain_untrusted_shape_or_down`。观察器允许“曲率中心与边界同向”的内在形状推荐，执行层却又无条件要求悬垂方向，且状态栏把实际拒绝原因隐藏成“等待反馈”。这是条件不一致，并非用户没有开启自动模式。

现统一为：有合格悬垂方向时沿用原流程；没有时，只接受观察器已经持续确认的**那一个等宽平移候选**，再核对候选形状、退出角、反馈新鲜度和目标连续性。该分支不宣称知道重力或已卸载，不借此开启任意扩缩。失去方向证据或交接角度不合适时仍可等待，现在显示具体条件。

另修复反向相位每帧重置数量历史：按累计相位路程保留最近π范围，方向真正反转或反馈中断才重置；保持同一相位不增加覆盖。状态显示独立的数量观测、各相位分组样本和交接原因，不再把`phase_hold=False`误标为“不等交接相位”。

`recommendation_fixture.json`保留一帧实机角度及原观察结果。在研究/实机两套类中均离线完成J8–J13→J7–J12及掩码变化；退出J13为2.90°。这是控制路径复现，固定观测与速度可用条件，不是重新跑实机闭环，也不能证明实机交接后的承重。

## 软件检查、同步及交接

9项针对性检查通过：反向/保持统计；不同初始幅值下相同实测形状的扩缩；离散逆算残差；日志推荐能执行；原参考积分匹配（关闭逆算补偿时）；重复时钟；较大截面目标减弯；实机/手调适配一致；飞特失能与只发送主动ID。随后增加同一推荐在实机嵌入类的复现并通过。无串口连接。

本轮动态记录使用新半圆/逆算内核，记录中没有无悬垂方向的推荐，因此最后的内在形状交接补丁由实机记录离线复现覆盖，未声称在物理闭环中验证这一分支。反向统计也只做软件检查，没有新增反向动力学。

运行命令：`conda run --no-capture-output -n mujoco python -X utf8 -m unittest validation.test_half_circle_window validation.test_measured_section_restore -v`。动力学入口`validation/half_circle_experiment.py`设两主例+一次有针对性修复上限；本轮只用两个主例。研究与单文件实机核心同步；手调默认`motor_angles`直接复用实机控制器。真实串口策略、热键、零位保留；历史接触反馈模式不属于本次角度控制。

当前研究目标部分满足：实测半圆方向的增减、缩径收紧和推荐执行通路已有证据，全过程严格形态与实机效果尚未验证完成。下一项最小验证是用户用同一实机调试方式检查J8–J13→J7–J12实际交接，并提供更新日志；先不扩大场景或继续跑仿真。研究若继续改进，优先处理启动时收紧先于数量判断，以及缩径后的离散交接/冲击。
