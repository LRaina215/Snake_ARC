# 18关节竖直Helix至水平ARC研究

**结论：18关节、110 mm裸管、300 mm弯曲半径、已知名义弯向/几何的代表病例，已完成竖直Helix→局部包绕跨弯→水平开放半圆→自动归中→续行。**通过例为elbow03，物理201.95 s；本轮不更新实机文件或热键入口，不宣称未知弯头自主跨越或实机通过。

首选一圈在本轮退尾中承载失败，采用目标1.5圈竖直承载及跨弯；水平侧搭稳后再用原逆向解缠退到约一圈，再成半圆。没有证明1.5圈是最小或最优包绕量。

完整视频：[正常速度](../../../artifacts/vertical_arc_20261108/elbow03/process_1x.mp4)、[4倍回放](../../../artifacts/vertical_arc_20261108/elbow03/process_4x.mp4)。视频来自保存的真实qpos，含斜视、沿局部管轴的显示切片、阶段、人工事件、相位、目标/实测角和使能。右侧管道切片仅用于回放可见性，不改变物理实验碰撞或支撑。

开始前假设、场景及验收见[执行方案](../../../docs/竖直Helix跨弯转ARC仿真实验方案.md)。当前新模型实际骨架25/72/91 mm，110 mm裸管、摩擦0.5，18个2.355 Nm扭矩电机，kp127/kd1，机械阻尼1.5；继承原19个机器人刚体各0.136 kg，动态机器人总质量2.584 kg。连接件增重/准确惯量尚未实测。仿真真值不进入控制器。

## pilot01：相位方向错误，失败保留

假设正相位推进可以向上；固定当前半径94 mm/螺距130 mm、一圈保留量，其余条件不变。验收先要求全Helix向上，再检查局部包绕净上移72 mm和窗口外零驱动力矩。

结果：全Helix阶段2–10 s实际头端下降169.54 mm，退出过渡仍向下，未进入局部爬升就因尾端距地小于50 mm终止。实际地面承托为0，不能把程序的floor停止标签写成已经落地。无保存帧自碰撞、失能电机力矩0；最大关节87.65°、跟踪误差10.25°，742个保存帧有饱和。

原因判断：相位符号与当前螺旋旋向/摆放方向组合相反，较高置信；还不能据此判断局部一圈承载失败。下一项最小验证仅反转相位速度复跑先导；增加初始攀爬失败提前结束，不继续无效退尾。本轮没有修改摩擦、力矩或机器人质量。

原始目标/实际状态/掩码/反馈与源码保留在本机artifacts/vertical_arc_20261108/pilot01。

## pilot02：方向修复成立，一圈局部化失败

仅把相位速度改为-0.5 rad/s。完整Helix阶段向上约142 mm，方向修复确认；退尾时曾持续向上至头端约2.04 m，但继续减少包绕后在约43–47 s失去承载，尚未达到计划一圈保持阶段。已查看覆盖全程的12时刻实际状态斜视，退出尾段确实逐段失能，而保留包绕缩短到约1.2圈时整体下滑。

该次末尾JSON导出遇到NumPy整数序列化错误，原始qpos/qvel、目标、使能、力矩已保存在trace.npz；未重跑物理，离线恢复阶段标签/接触评价，恢复说明写入run.json，不把重算接触冒称原始逐步接触。后续修复导出器。

原因判断：局部包绕承载/夹持裕量不足，中等置信；仅凭这例不能排除尾部退出过渡造成的偏载。下一项最小验证把保留量改为1.5圈，其余条件固定，区分“包绕缩短过度”与“退出过程本身不可用”。不改变摩擦、力矩或质量。

## pilot03：1.5圈先导通过

只增加保留包绕到1.5圈，固定方向-0.5 rad/s及其余物理条件。完整Helix净上移140.94 mm；局部爬升阶段35–49.95 s净上移193.54 mm，超过72 mm。所有保存帧失能电机力矩0，无触地/自碰撞；最大关节86.98°，最大跟踪7.64°，1000帧有饱和。此例只证明局部承载/推进可行，不能声称力矩裕量充足。下一主例采用1.5圈，暂不再调试强制一圈。

## elbow02：首次跨弯走到归中，但未通过

此前elbow01因场景numeric元数据容量超限而未开始物理；elbow01a在12 s遇到研究核心重构的pitch字段遗漏，只有源码/假设及控制台记录，未成功冲洗原始状态，这个证据缺口保留说明。修复字段并增加异常存档后，elbow02完成146.55 s物理运行；仿真真值仅用于记录明确的操作者事件。

实际局部包绕49.3 s开始迁移过弯；113.5 s在水平侧接受支撑确认，随后状态机走到成弧、归中和续行。保存实际状态中，117.55–121.75 s发生81帧自接触（头/尾及退出段互碰），最大跟踪48.21°；最终续滚中心向弯头退回132.67 mm，不能报完整通过。

原因判断：把1.5圈直接交给原先按约一圈设计的半圆成形，退出头/尾段互相扫过；且当前安装/旋向下，水平续滚相位符号错误。已检查全程斜视序列，前半跨弯未出现相同自接触。下一项最小修复：水平侧先用原逆向解缠从1.5圈退到一圈，再进入原成弧；修正新研究控制器的续滚方向，竖直和跨弯曲线参数不变。

固定elbow02的场景、起态、驱动、1.5圈保留、跨弯速度和模拟人工事件条件，仅修复水平接管后的退圈/成弧顺序及续滚符号。全程实际保存态复核及覆盖全阶段的斜视/端视序列已检查；最终结果见[独立评价摘要](results.json)。

## 控制输入、复用和可观测范围

- 竖直/跨弯参考不使用重力投影强行确定顶部；用Bishop参考方向及材料相位连续传递，管轴从竖直到水平时不除以近零重力投影。
- 弯轴包绕先按蛇身弧长重参数化，曲率分量由公共CurveGait.sampled_targets进行相邻连杆积分。它与原线/圆弧/螺旋积分的直轴极限核对误差小于0.3°；目标仍由曲线积分产生。
- VerticalArcTransition继承原HelixArcTransition的apply_reference，复用同一实测角预置/限速；水平侧调用原HelixArcManual、公共归中工厂与端部处理。局部Helix拟合只使用仍在包绕内的角反馈，不把被动尾端全零稀释成错误的大半径。
- 控制输入是200 ms角反馈、20 ms命令时钟、已发目标/使能、机械尺寸、名义110/300 mm几何和操作者事件。49.3/113.5 s两个事件由实验脚本读取世界姿态模拟操作者触发，来源写在operator.json；属于人工确认，不是未知障碍自主识别，也不是连续真值位置闭环。
- 曲线进给为固定命令参数，未把真实根位姿、接触力或真实距离误差输入控制器。独立评价使用世界管轴、接触和实际骨架；接触力不是实机已获得的信息。

## 数量、记录及适用边界

本轮共3次先导、2次完整跨弯，以及1次12 s程序错误中断的部分物理运行；另1次仅初始化失败。每个增补均对应上面的已知失败，不做场景/摩擦扫描。最后一次完整病例通过后停止动力学，没有增加延迟、低阻尼或长hold测试。

实验早版对elbow病例的hypothesis文字仍沿用先导模板；本轮跨弯预设目标以事前已提交的执行方案、case=elbow及本报告独立评价口径为准。原hypothesis不回写，后续实验入口已区分两类目标。旧run.json的passed仅用于先导快速验收，elbow的最终判定以review.json为准，避免以状态机完成替代形态验收。

原始状态、失败源码/参数、目标、掩码、力矩、曲线参数与操作者事件保存在本机artifacts/vertical_arc_20261108/；小型[模型审查](model_audit.json)、[结果摘要](results.json)随Git保存。pilot02的导出恢复和elbow01a未冲洗原始状态的证据缺口已明确记录，不补造原始数据。

24项相关软件检查通过：新曲线积分直轴极限、跨竖直/弯头/水平参考连续、公共接管串接，以及既有曲线/归中/单步/端部处理相关回归。实机文件、现有热键入口未改。没有运行单独实机或连接串口。

本轮满足当前代表场景的流程实现目标；未验证未知弯头、不同起态周向、其他管径/弯曲半径、40关节或实机。下一项最小工作由用户验收视频后确定；若要移植，应先保留名义几何和人工确认的输入边界，而不是声称已经能自动定位任意弯头。

## 复现与文件

沿用mujoco Conda环境，在仓库根目录运行；输出目录必须选一个尚不存在的名字，避免覆盖失败记录。

```powershell
conda activate mujoco
python tools/build_vertical_arc_scene.py
python validation/vertical_arc_experiment.py --case pilot --output artifacts/my_vertical_pilot
python validation/vertical_arc_experiment.py --case elbow --output artifacts/my_vertical_elbow
python validation/review_vertical_arc.py artifacts/my_vertical_elbow
python validation/render_vertical_arc.py artifacts/my_vertical_elbow --speed 1
```

当前默认相位-0.5 rad/s、保留1.5圈，elbow起始头高1.0 m、pilot为1.42 m；没有改原实机全局配置。研究控制在snake_control/vertical_arc_transition.py，弯轴参考在bent_helix_curve.py，模型构建在tools/build_vertical_arc_scene.py；共享曲线积分和水平接管仅扩展库接口，未重新内嵌到实机单文件。
